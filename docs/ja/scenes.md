# シーン

[English](../scenes.md) | [中文](../zh/scenes.md) | [Русский](../ru/scenes.md) | [Tiếng Việt](../vi/scenes.md) | 日本語 | [한국어](../ko/scenes.md)

コンパニオンは一度にちょうど 1 つのシーンを表示します。シーンは Web クライアントがすでに
公開しているライブのファクトから選ばれ、プロンプトのテキストから推測されることはなく、
モデル呼び出しも行われず、ユーザー自身の入力でシーンが変わることもありません。ルールは
`src/client/state.ts`（`deriveScene`）にあり、`tests/state.test.ts` でカバーされています。
シーンのキャプションは 6 言語でローカライズされ（`src/client/text.ts`、`SCENE_LABELS`）、
ルール自体は言語に依存しません。

## 入力

| ファクト | 取得元 | 意味 |
| --- | --- | --- |
| `running` | ファクトブリッジ経由の `SessionSnapshot.running` | Host 上でターンが実行中 |
| `pendingInteraction` | `useSessionStatus(…)` → `status.pendingInteraction` | 承認または質問がユーザーを待っている |
| `inputPhase` | ファクトブリッジ経由の `InputState.phase` | `plain`、`adjudicating`、`claimed`、`submitting`、`sending` |
| `toolRunning` | ブリッジ経由で `ChatSnapshot.legacy.runningCalls` が空でない | ツール呼び出しが今まさに実行中 |
| `assistantStream` | ブリッジ経由で `ChatSnapshot.legacy.partial.blocks[].kind` と空でない `text`（`reasoning` または `text`） | アシスタントが今ストリーミングしている内容 |
| `error` | `SessionSnapshot.promptError` または `lastAgentError` | 送信またはエージェントのエラーが報告された |
| `openError` | `SessionSnapshot.openState === 'error'` | セッション履歴を開けなかった |
| `runningMs` | `running` が true になってからの時間 | 現在の実行の継続時間 |
| `idleMs` | 最後のセッション/ターン変更からの時間 | スリープタイマーに使用 |
| `flash` | 停止失敗後のローカル 4.8 秒タイマー | エラーのフラッシュ。正常な停止は代わりに固定表示になる |

ライブビットは `CompanionFacts.live`（1 = ツール呼び出し実行中、2 = 推論ストリーミング中、
4 = 回答テキストストリーミング中）としてオーバーレイに届き、Chat スナップショットと同じ
フレーム内で公開されるため、ライブなシーン変更は実質的に即時です。1 秒クロックは経過時間の
段階とスリープタイマーにのみ使われます。

ファクトは `conversation.input.dock` の非表示ブリッジエントリが公開し、オーバーレイが
読み取ります。会話がマウントされていないときは、最後のファクトが `connected: false` と
`running: false` を伴って保持されるため、オーバーレイは待機/休眠の挙動にフォールバック
します。承認待ちは会話以外のページでも表示されます。オーバーレイ自身も
`useSessionStatus` を購読しているためです。

## ルールの順序

最初に一致したルールが優先されます：

```text
openError                          -> error
pendingInteraction                 -> waiting
inputPhase sending/submitting/adjudicating -> typing
toolRunning                        -> working
assistantStream === 'reasoning'    -> thinking
assistantStream === 'answer'       -> typing
running:
    runningMs > 180 000            -> coffee
    runningMs >  75 000            -> tired
    otherwise                      -> thinking   (request in flight, no live stream)
flash === 'error' or error         -> error
flash === 'success'                -> success
idleMs > 110 000                   -> sleeping
otherwise                          -> idle
```

`success` 用の `flash` ルールは今も `deriveScene` に残っていますが、オーバーレイは時間制の
success フラッシュを生成しなくなりました。正常な停止は固定表示の `success`（完了）として
適用されます（後述）。4.8 秒の時間枠を保つのはエラーフラッシュだけです。ライブビットは
クロックに縛られないため、おおよそ 1 秒の粒度を持つのは経過時間の段階（`tired` /
`coffee`）とスリープタイマーだけです。

## 固定表示の完了と詳細パネル

正常な停止は固定表示です。オーバーレイは、ユーザーがコンパニオンにホバーするか（320 ms の
滞在時間により、レポートへ向かう途中でポインタが通過しただけでは閉じません）、新しい
ターンが始まるまで、`success` とその 1 行レポートを保持します。ホバーするとカードは閉じ、
シーンは `idle`/`sleeping` に戻ります。新しく終わったターンはカードを再び開きます。完了した
結果がまだ見られていない間、コンパニオンが眠り込むことはありません。

レポート行にはプレビューとローカライズされた**詳細**ボタンが表示されます。ボタンを押すと、
完全な最終回答をプレーンテキストとして表示するスクロール可能なパネルが開きます。React に
よってエスケープされ、HTML や markdown のレンダリングは行われず、改行は保持され、8000 文字
に制限されて省略記号が付きます。パネルはコンパニオンの上または下に配置され、ビューポート内
にクランプされます。✕、Escape、外側のクリックで閉じ、完了が閉じられると非表示になります。
レポートのテキストは `role="status"` / `aria-live="polite"` を保ち、ボタンは
`aria-expanded` を公開し、パネルは**レポート**というタイトルの `role="dialog"` です
（6 言語すべてでローカライズ）。パネルが開いている間はレポート/入力カードが置き換えられ、
閉じるとカードが復元されます。

レポートとホバー時のメッセージ入力欄は、コンパニオンの下（または上）に固定された 1 つの
ビューポートクランプ列を共有します。レポートが表示されている間、入力欄はその直下に位置し、
詳細ボタンはレポート行に残ります。レポートにホバーすると開いたままになり、入力欄が現れます。
コンパニオンにホバーすると 320 ms の滞在時間の後にレポートが閉じ、その後は入力欄が
コンパニオンの直下に位置します。レポートから離れると入力欄は再び隠れ、レポートはスプライト
にホバーするか新しいターンが始まるまで残ります。この列と詳細パネルはコンパニオンの選択した
サイズに追随します（**サイズ**スライダーは 50% から 200% の範囲で、50/100/150/200% の
プリセットチップ付き。同じ操作は**設定 → 一般 → コンパニオンの大きさ**にもあります）。

## 移動用のビジュアル（`roaming`）

`roaming` はシーンではなく移動用のビジュアルです。`SCENES` には含まれず、`deriveScene` が
返すこともなく、キャプションやルールもありません。ユーザーが Deepy をドラッグしている間、
オーバーレイは現在のシーンの代わりに、机のない `roaming` アニメーション
（オプション）を描画します。机、ノート PC、ランプ、床が彼と一緒に移動することはありません。離すと現在の
シーンに戻ります。Whale Girl には roaming 用のアセットがないため、移動中も彼女のシーンの
スプライトを保ちます。デスクトップウィンドウも、ウィンドウを移動している間は同じことを
します。上記の 15 状態のルールは変わりません。

## 各シーンが主張できること

| シーン | 安全に言えること |
| --- | --- |
| `idle` | 何も観測されていない |
| `typing` | 送信が進行中、またはアシスタントが回答テキストをストリーミング中 |
| `working` | ツール呼び出しが実行中 |
| `thinking` | アシスタントが推論をストリーミング中、またはモデルへのリクエストが進行中。ユーザーの入力中ではない |
| `tired` | ライブ信号のない長時間実行。比喩であり、モデルの疲労ではない |
| `coffee` | ライブ信号のない非常に長い実行。見た目だけのもの |
| `waiting` | 何かがユーザーを待っている |
| `success` | エラーが観測されずに実行が停止した。キャンセルを含む。コンパニオンにホバーするか新しいターンが始まるまで固定表示 |
| `error` | 本物のエラー信号 |
| `sleeping` | 110 秒間セッションの変化なし。表示専用 |
| `planning`、`reading`、`searching`、`debugging`、`offline` | 手動プレビュー専用。クライアントはまだ型付きの信号を持たない |

`thinking` はアシスタント自身の作業についてのものであり、ユーザーがメッセージを書いている
ことについてではありません。下書きを入力しても何も変わらず、アシスタントが実際に作業を
始めるまでコンパニオンは `idle` のままです。`tired`、`coffee`、`sleeping`、`success` を
モデルに関する事実として提示してはいけません。これらは粗いクライアント状態に対する表示上の
比喩です。

## 手動プレビュー

歯車パネルには 15 シーンすべてがサムネイルとして並び、キャプションは選択中の UI 言語で
表示されます。1 つを選ぶと、**自動**を押すかセッションが変わるまでそのシーンが強制され
ます。強制したシーンが永続化されることはありません。パネルには**閉じる**もあります
（Escape でも閉じます）。

## シーンの追加・名前変更

1. `src/client/state.ts` の `SCENES` にシーンを追加し、`deriveScene` のルールにも追加します。
2. `src/client/text.ts` の `SCENE_LABELS` に、6 言語すべてのキャプションを追加します。
3. `assets/girl/<scene>.{webp,png}` と `assets/whale/<scene>.{webp,png}` を追加します
   （192×128、透明背景。WebP は 120 ms で 16 フレーム）。
4. `npm run build` を実行します。アセットマニフェストとクライアントのバンドラーが新しい
   ファイルを拾います。
5. 新しいルールのために `tests/state.test.ts` を拡張します。

## 動きの低減

`prefers-reduced-motion: reduce` が一致する場合、またはユーザーが**アニメーション**を
オフにした場合、アニメーション WebP の代わりにそのシーンの静止 PNG が描画されます。この
判定はシーンが変わるたびに実行されるため、OS レベルの変更はリロードなしで反映されます。
