# デスクトップウィンドウ

[English](../desktop.md) | [中文](../zh/desktop.md) | [Русский](../ru/desktop.md) | [Tiếng Việt](../vi/desktop.md) | 日本語 | [한국어](../ko/desktop.md)

`desktop/companion.py` は、ブラウザの外に同じピクセルコンパニオンを表示する**オプションの
スタンドアロンなデスクトップウィンドウ**です。フレームなし、常に手前、ピクセル単位で透明で、
マウスの左ボタンでドラッグでき、右クリックメニューを持ちます。素の Python 3 プログラム
（PyGObject 経由の GTK 3、Pillow、そして小さな localhost HTTP ブリッジ）であり、Harness
プラグインではなく、Web GUI も変更しません。

ウィンドウがスプライトで、Web ページが頭脳です。ブラウザ側の半分は通常のバンドルの一部で、
コンパニオンの設定パネルで**デスクトップウィンドウ**をオンにするまで待機します。既定は
オフなので、デスクトップアプリのないページがローカルポートを調べることはありません。両方の
半分は同じマシン上で動かす必要があります。ブリッジは `127.0.0.1` にのみバインドし、認証は
ありません。

状態はアシスタント自身の作業、つまり実行中のツール呼び出し、ストリーミング中の推論や回答
テキスト、進行中のリクエストを追跡するようになり、デスクトップのミラーも同じシーンを表示
します。ブリッジのプロトコルは変わっていません。ブラウザは終了したターンの `success` と
レポートを固定表示で保持するため、デスクトップウィンドウはページが保持している間ずっと
`success` をミラーリングします。レポート行とその詳細パネルはブラウザ専用です。

## 動作要件

- ブラウザのページと同じマシン上の Python 3.10+。
- PyGObject、Cairo バインディング、Pillow を備えた GTK 3：

```sh
sudo apt install python3-gi gir1.2-gtk-3.0 python3-cairo
python3 -m pip install --user Pillow
```

ウィンドウをピクセル単位で透明にするのは `python3-cairo` です。これがない場合（または
コンポジットを有効にしたウィンドウマネージャーがない場合）もウィンドウは動作しますが、
スプライトを濃い単色の背景の上に描画します。`desktop/requirements.txt` には pip 用の
`PyGObject>=3.42` と `Pillow>=10` が記載されています。PyGObject は通常ディストリビューション
から導入するもので、pip からではありません。

スプライトのフレームはリポジトリの `assets/` ディレクトリ（`assets/girl/`、
`assets/whale/`）から取得します。チェックアウトであれば追加のダウンロードは不要です。

## 実行する

リポジトリのルートから：

```sh
python3 desktop/companion.py
# or
./desktop/run.sh
```

| フラグ | 意味 |
| --- | --- |
| `--port PORT` | ブリッジのポート。既定は `37421`。このバージョンではページが常に `37421` を調べるため、既定のままにしてください。 |
| `--assets DIR` | アセットディレクトリ。既定はリポジトリの `assets/`。 |
| `--scale 0.5\|…\|2.0` | 初期のスプライトスケール。`0.5` から `2.0` までの任意の値（1% に丸め）。範囲外の値は使用法エラーで終了します。以降の見た目は右クリックメニューが担当します。 |
| `--no-animation` | アニメーション WebP ではなく静止 PNG で開始します。 |
| `--lang en\|ru\|zh\|vi\|ja\|ko` | 予約済み。ウィンドウはテキストを描画しないため、見た目は変わりません。 |
| `--stale-ms MS` | 古いとみなす時間枠（ミリ秒）。テスト用フックで、既定は `10000`。 |
| `--self-test` | ヘッドレスの受け入れテストを実行して終了します。ディスプレイは不要です。 |

ページが最初の状態を送るまで、ウィンドウは `offline` で始まります。設定（見た目、位置、
常に手前）は `~/.config/dsh-pixel-companions/desktop.json` に保存されます：

```json
{"character": "girl", "scale": 1, "animation": true, "alwaysOnTop": true, "x": 1200, "y": 600}
```

初回実行時、そのファイルに保存されたキャラクターがなければ、最初のブラウザからの
ペイロードがキャラクターを選べます。その後はメニューが正であり、ペイロードはシーンだけを
動かします。保存された `scale` は `0.5` から `2.0` までの任意の値（1% に丸め）を受け付け、
旧来の `0.8` / `1` / `1.2` の値も引き続き読み込めます。

## ブラウザ側を有効にする

1. **設定 → プラグイン**でバンドルが有効になっていて、Web ページが開いていることを確認
   します（通常は `http://127.0.0.1:3080`）。
2. デスクトップウィンドウを起動します（後から起動しても構いません。ページは 10 秒ごとに
   再プローブします）。
3. コンパニオンの歯車パネルを開き、**デスクトップウィンドウ**にチェックを入れます。

行には現在の状態が表示されます：

| 状態 | 意味 |
| --- | --- |
| **オフ** | 無効。ページはデスクトップのポートをまったく調べません。 |
| **未起動** | 有効だが、`127.0.0.1:37421` で応答するものがありません。 |
| **接続済み** | デスクトップウィンドウが最後のプローブに応答しました。シーンがミラーリングされています。 |

**デスクトップウィンドウ**がオンの間は、行の直下にプレビューカードが現れます。市松模様の
背景を持つステージに、デスクトップウィンドウが描画するのとまったく同じスプライト（同じ
キャラクター、シーン、アニメーションの状態、ドット感を保つスケーリング）が表示され、タイトルは
**デスクトップウィンドウのプレビュー**です。緑の**接続済み**、または琥珀色の
**⚠ 未起動 — `desktop/companion.py` を実行してください**が表示されます。カードは表示専用で、
ボタンもプロトコルの変更もなく、オプションをオフにすると消えます。行にホバーしても同じ
起動のヒントが表示されます。

有効かつ接続済みの間、ページは 10 秒ごとに `GET /health` を調べ、シーンや見た目が変わった
ときに状態をポストし、4 秒のハートビートを送ります。ウィンドウはポストからおよそ 120 ms
以内に変更を反映します。ライブ状態のためにはページを開いたままにしてください。10 秒を超えて
状態が届かない場合（ページを閉じた、再読み込み中、ネットワークが遮断された）、ウィンドウは
`offline` を表示し、動作を続けます。

## 右クリックメニュー

- **キャラクター** — Lumi（`girl`）または Deepy（`whale`）。
- **アニメーション** — アニメーション WebP、または静止 PNG。
- **サイズ** — 50%、75%、100%、125%、150%、200%。
- **常に手前** — ウィンドウの最前面表示のヒントを切り替えます。
- **位置をリセット** — 右下の既定位置に戻します。
- **1 時間隠す** — ウィンドウを隠します。1 時間後に自動で再表示されます。
- **終了** — 設定を保存して終了します。

スプライト上のどこでも左ドラッグするとウィンドウが移動し、位置が保存されます。ウィンドウの
移動中、Deepy は机なしの `roaming` アニメーションに切り替わり、離すとミラーリング中の
シーンに戻ります。Whale Girl はシーンのスプライトを保ちます。これは移動用のビジュアルだけの
話で、ブリッジのプロトコルと 15 シーンのセットは変わりません。ウィンドウはフレームなしで
トレイアイコンもないため、右クリックの**終了**で閉じます。

## ローカルブリッジとプライバシーの境界

ベース URL：`http://127.0.0.1:37421`。ブリッジはループバックインターフェースにのみ存在する
小さな HTTP サーバーです。

| リクエスト | 応答 |
| --- | --- |
| `GET /health` | `200` `{"ok":true,"v":1}` |
| `POST /state` | `204`、本文なし |
| `OPTIONS /state`、`OPTIONS /health` | CORS ヘッダー付きの `204`（`Access-Control-Allow-Origin: *`、メソッド `GET, POST, OPTIONS`） |
| 不明なパス | `404` |
| 不正な JSON、不明なシーン、長さの欠落または不正、8 KB 超の本文 | `400` |

`POST /state` のペイロード（最大 8 KB。不明なフィールドは無視されます）：

```json
{"v": 1, "scene": "typing", "character": "girl", "scale": 1, "animation": true, "updatedAt": 1780000000000}
```

`scene` は 15 のシーン id（`idle`、`typing`、`thinking`、`planning`、`reading`、
`searching`、`working`、`success`、`waiting`、`error`、`tired`、`coffee`、`sleeping`、
`debugging`、`offline`）のいずれかです。毎回のポストで使われるのは `scene` だけで、
`character` はキャラクターが保存される前の初回実行時にのみ採用され、`scale` と
`animation` はデスクトップメニューの担当で、`updatedAt` は情報提供用です。

ブリッジを通過するのは表示状態だけです。**プロンプトのテキスト、下書きテキスト、
メッセージ、セッション id、ファイルパス、モデル出力が送られることは決してありません**。
ブリッジは：

- `127.0.0.1` にのみバインドし、認証も Cookie も TLS も持ちません。
- 8 KB を超えるリクエスト本文と、シーン id が不明な本文を拒否します。
- リクエストのペイロードをログに記録せず、ファイルも配信しません。
- ローカルページがポストできるようにするためだけに、CORS でブラウザのオリジンを許可します。

## 古さとオフラインの挙動

ウィンドウは最後に受信した状態と、それが届いた時刻を覚えています。10 秒を超えて状態が
届かなければ `effective_scene` は `offline` になり、新しいポストが届くまでウィンドウは
描画を続けます（アニメーションがオンのときはそのシーンのアニメーションも続けます）。ページ側も
これを反映し、ヘルスプローブやポストが失敗すると設定行は**未起動**にフォールバックします。

ちょうど 10.000 秒はまだ新鮮とみなされ、切り替えはその直後に起こります。`--self-test` は
注入したクロックでこの境界を確認します。

## 検証

ヘッドレスで確認できる部分は検証済みです：

```sh
python3 -m py_compile desktop/companion.py
python3 desktop/companion.py --self-test
```

セルフテストは両方のキャラクター × 15 シーンすべてを 0.5、1.0、2.0 のスケールでデコードし、
さらに Deepy のオプションの `roaming` アニメーションも確認し、フレームのサイズと継続時間を
検証し、視覚的な証拠として 30 枚の先頭フレーム PNG をリポジトリ外の一時ディレクトリへ書き出し、
一時ポートでブリッジを起動して `GET /health`、両方の CORS プリフライト、有効な
`POST /state`、不正な本文や不明なシーンの本文（`400`）、不明なパス（`404`）を試し、最後に
10 秒の古さのルールを確認します。`ok:` のサマリー（`ok: … 92 animated decodes, 31 still decodes, 30 evidence PNGs, 260 checks`）を出力し、失敗時は非ゼロで終了します。

roaming の切り替えテストも通ります（`whale: moving→roaming, released→idle; girl: no roaming`）。ブラウザ側のペイロードはヘッドレスの React レンダーで検証され
（`scene=typing` → `success`）、リクエスト本文に下書きやセッションデータは含まれません。
さらにヘッドレスのブラウザドラッグテストでは、クジラがドラッグ中に `roaming` へ切り替わり、
離すとシーンに戻ることが示されます（少女は変わりません）。

グラフィカルセッションなしでは検証できないもの：実際のウィンドウ、Cairo ブリッジのない
マシンでのピクセル単位の透明化（そこでは不透明なフォールバックが想定されます）、常に手前と
ドラッグの挙動、Wayland でのウィンドウ配置。

## 制限事項

- グラフィカルセッション（X11 または Wayland）が必要です。ヘッドレスサーバーや素の WSL には
  ディスプレイがないため、X フォワーディングか仮想ディスプレイを使うか、`--self-test` を
  実行してください。
- Wayland のコンポジターは要求されたウィンドウ位置を無視することがあり、一部のバックエンドは
  ウィンドウ移動のリクエストを拒否します。X11 セッションがもっとも予測しやすいです。
- トレイアイコン、通知、ウィンドウ装飾、テキストはありません。閉じるには右クリックの
  **終了**（または**1 時間隠す**）を使います。
- ライブ状態のためにはページを開いたままにする必要があります。ウィンドウは表示先であり、
  2 つ目のクライアントではありません。
- 同じマシン上のみ：ブリッジはループバック専用で認証がないため、ポートを公開しないで
  ください。ウィンドウは小さなペイロードを超えて会話へアクセスすることはありません。
- HTTPS で配信されるページは通常、`http://127.0.0.1` へのリクエストを混合コンテンツとして
  ブロックします。通常の `http://127.0.0.1:3080` のページを使ってください。

## トラブルシューティング

| 症状 | 確認事項 |
| --- | --- |
| ウィンドウがまったく現れない | ディスプレイは利用できますか？ まず `python3 desktop/companion.py --self-test` を実行してください。サーバー上では X フォワーディングか仮想ディスプレイを使ってください。 |
| `cannot listen on 127.0.0.1:37421` | 別のコンパニオンインスタンスが動作中です。終了させてください（ページは 37421 を使うため、既定のポートのままがもっとも簡単です）。 |
| 透明にならず濃い単色の矩形になる | `python3-cairo` をインストールし、コンポジットを有効にしたウィンドウマネージャーを使い、X11 またはコンポジット対応の Wayland セッションで実行してください。これは想定された不透明フォールバックであり、クラッシュではありません。 |
| シーンが `offline` のまま | ページが開いていて、バンドルが有効で、**デスクトップウィンドウ**がチェックされていますか？ `curl http://127.0.0.1:37421/health` を確認し、ページとウィンドウが同じポートを使っていることを確かめてください。 |
| ウィンドウが開いているのに設定が**未起動**になる | ページがブリッジに到達できていません。ポート、ローカルのファイアウォール、37421 を使う別のプロセス、HTTPS で配信されるページ（混合コンテンツ）を確認してください。 |
| Wayland でウィンドウを移動できない | コンポジターが移動リクエストを無視することがあります。X11 セッションを試すか、スプライトの別の場所からドラッグしてください。 |
| ウィンドウが別のモニターにある / 画面外にある | 右クリックメニューの**位置をリセット**を使ってください。Wayland コンポジターによっては配置をまったく無視します。 |

[troubleshooting.md](troubleshooting.md) を参照してください。
