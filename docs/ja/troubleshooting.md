# トラブルシューティング

[English](../troubleshooting.md) | [中文](../zh/troubleshooting.md) | [Русский](../ru/troubleshooting.md) | [Tiếng Việt](../vi/troubleshooting.md) | 日本語 | [한국어](../ko/troubleshooting.md)

## コンパニオンが見つからない

1. **バンドルは有効ですか？** 設定 → プラグイン → プラグイン一覧。エントリ名は
   *Pixel companions* です。`disabled` と表示されていれば有効にしてください。
2. **非表示になっていませんか？** 設定パネルには**表示**スイッチがあります。オフのときは
   コンパニオンの位置に小さな 🐳 ボタンだけが残ります。クリックするとコンパニオンが戻ります。
3. **ページを再読み込みしてください。** 新しくインストールしたバンドルは通常 1〜2 秒で
   ホットスワップされますが、再読み込みは常に安全です。コンパニオンはフレーム全体を覆う
   オーバーレイに描画されるため、開いている会話は不要です。設定やプラグインを含むすべての
   ページに表示されます。
4. **Host を再起動してください。** `dsh web` プロセスを `Ctrl+C` で止め、もう一度起動します。
   `package.json` の変更（バージョンの引き上げなど）には再起動が必要です。
5. **プロファイルを確認してください。** `dsh --profile web --dump-config` に
   `dsh-pixel-companions` という行が表示されるはずです。表示されなければバンドルが登録
   されていません。`dsh plugin --profile web add link:"$PWD"` をもう一度実行してください。

## コンパニオンは表示されるが固まっている

- 設定パネルで**アニメーション**がオフになっているか、OS が動きの低減を要求しています
  （`prefers-reduced-motion: reduce`）。どちらも仕様どおり静止 PNG を描画します。
- シーン自体が静止画のようなシーン（`sleeping`、`waiting`）である可能性があります。
  スプライトの上のキャプションを確認してください。

## ドラッグしてもコンパニオンが動かない

- 周囲の空白ではなく、**スプライト自体**（コンパニオンが非表示のときは 🐳 ボタン）を
  ドラッグしてください。オーバーレイ層は仕様上クリック透過です。
- 離す前に 3 ピクセルのドラッグしきい値を超えて押して動かしてください。それより短い押下は
  クリックとして扱われ、設定パネルが開きます。
- マウス、タッチ、ペンすべてで動作します。マウスのセカンダリボタンではドラッグは始まり
  ません。
- 位置が古い、またはポインタが固まっているように見える場合は、歯車を開いて
  **位置をリセット**を選び、もう一度試してください。

## コンパニオンが大きすぎる、または小さすぎる

**設定 → 一般 → コンパニオンの大きさ**、またはコンパニオンの ⚙ ポップオーバーを開きます。
どちらも同じ操作を表示し、同じ設定を編集します。もっとも手早いのはサイズ行の下にある
**50/100/150/200%** のプリセットチップです。微調整には**サイズ**スライダー（50–200%、
5% 刻み、−/+ ボタンとリアルタイムのパーセント表示付き）を使います。スプライトは実際の
スケール後のピクセルサイズで描画されるため、ヒットエリア、キャプションと歯車、
レポート/入力の列、詳細パネルもそれに追随します。サイズが変わると保存された位置は自動で
再クランプされ、コンパニオンが扱いにくい場所に来てしまった場合は**位置をリセット**で自動の
右下位置に戻ります。どちらの操作も表示されない場合、ページは古いクライアントバンドルで
動作しています。ハードリロードしてください（バンドルを更新したばかりなら `dsh web` も
再起動します）。

## ホバー時のメッセージ入力欄が表示されない

1 行の入力欄が開くのは、マウスでコンパニオンにホバーしたときだけで、しかも会話がマウント
されていて、コンポーザーが利用可能で、コンパニオンが表示されている場合に限られます。
コンパニオンをドラッグしている間や設定パネルが開いている間は非表示で、タッチデバイスでは
開きません。ポインタをスプライトの上に置いてそのままにしてください。入力欄はコンパニオンの
下（または上）に位置し、ビューポート内にクランプされます。完了レポートが表示されている間、
入力欄は同じクランプ列のレポート直下に位置します。レポートにホバーすると入力欄が現れ、
レポートは開いたままになります。一方、レポート行とその**詳細**ボタン自体はメッセージ
入力欄を開きません。スプライトにホバーすると 320 ms の滞在時間が始まり、固定表示の完了が
閉じられます。閉じた後は入力欄がコンパニオンの下に戻ります。レポートから離れると入力欄は
再び隠れ、レポートはスプライトにホバーするか新しいターンが始まるまで残ります。

## メッセージ入力欄が下書きを飲み込んでしまった

入力欄はコンポーザー経由で送信し（`setDraft` + `submit`）、メッセージをキューに入れた直後に
以前のコンポーザーの下書きを復元します。その瞬間にコンポーザーが送信や受け付けの段階で
ロックされていると、復元に失敗して下書きが失われることがあります。空の下書きは空のまま
残ります。必要なら下書きを入力し直してください。入力欄からの送信がセッション履歴を変える
ことはありません。

## 完了レポートが表示されない

レポートは固定表示です。ターンが正常に終わると、1 行プレビュー（最初の空でない行、
120 文字以下、markdown 記法を除去）が、コンパニオンにホバーするか新しいターンが始まるまで
残ります。320 ms のホバー滞在で閉じますが、レポート行自体へのホバーでは閉じません。一度
閉じても、次に終わったターンで再び開きます。回答が空の場合は何も表示されず、**詳細**ボタン
は確定したアシスタントの回答がテキストを提供したときにだけ現れます。ボタンがある場合は、
完全な回答を上限付きのプレーンテキストとして開きます。

## モニターやウィンドウサイズを変えた後、コンパニオンが画面外にある

位置はビューポート内にクランプされ、リサイズ時に再クランプされますが、モニターの変更、
ズームの変更、非常に小さいウィンドウの後では、保存された位置が扱いにくいままになることが
あります。歯車を開いて**位置をリセット**を選ぶと、コンパニオンは自動の右下位置に戻り、
再びウィンドウのリサイズに追随し始めます。`localStorage` の `position` フィールドを消去
しても同じ結果になります。

## 設定パネルが切れている、または画面外に開く

パネルはコンパニオンを基準に配置され、利用可能な余地に応じて上下に反転し、ビューポート内に
クランプされます：

- コンパニオンが隅にある場合は、パネルを開く前に中央方向へドラッグしてください。
- **位置をリセット**で既定位置に戻ります。
- 異常に小さいウィンドウではパネルがスクロールします。それでも使いにくければ、ウィンドウを
  リサイズするかサイズを報告してください。

## アートワークを変更した後、スプライトが古い、または 404 になる

スプライトの URL にはコンテンツハッシュ（`?v=<sha1-8>`）が含まれ、マニフェストはビルド時に
生成されます。`assets/` 以下のファイルを置き換えたら `npm run build` を実行して
`src/client/assets.generated.ts` と `client.js` を再生成し、それからページを再読み込みして
ください。古いアートがまだ表示される場合は、キャッシュされたドキュメントを捨てるために
ハードリロードを行います。404 は、インストール済みパッケージにもう `assets/` ツリーが
含まれていないことを意味するので、バンドルを再インストールしてください。

## デスクトップウィンドウが開かない

デスクトップアプリはバンドルの一部ではなく、独立した Python プロセスです。チェックアウトから
`python3 desktop/companion.py`（または `./desktop/run.sh`）で起動します。

- **ディスプレイがない。** ウィンドウには X11 または Wayland が必要です。サーバー上では
  `ssh -X`、XWayland を備えた Wayland セッション、または仮想ディスプレイを使ってください。
  素の WSL ホストには X サーバーが必要です。画面を必要としない部分はすべて
  `python3 desktop/companion.py --self-test` で確認できます。
- **ポートが使用中。** `cannot listen on 127.0.0.1:37421` は、別のコンパニオンインスタンスが
  動作していることを意味します。終了させてください。ページは常に 37421 を調べるため、既定の
  ポートを保つのがもっとも簡単です。
- **GTK または Pillow がない。** スクリプトが PyGObject/GTK のメッセージや Pillow の
  `ImportError` で終了します。`python3-gi gir1.2-gtk-3.0` をインストールし、
  `python3 -m pip install --user Pillow` を実行してください。

## デスクトップウィンドウが不透明な暗い箱になる

Cairo バインディング、またはコンポジットを有効にしたウィンドウマネージャーがない場合、
ウィンドウは仕様どおりスプライトを濃い単色の背景の上に描画します。`python3-cairo` を
インストールし、コンポジット対応の WM/セッションを使い、ウィンドウを再起動してください。

## デスクトップウィンドウが `offline` のまま

- ページを開いたままにし、歯車パネルで**デスクトップウィンドウ**にチェックを入れておく必要が
  あります。行には**オフ**、**未起動**、**接続済み**が表示されます。オンのときは、行の下の
  プレビューカードが状態を繰り返し、起動コマンドを示します。行へのホバーでも同じヒントが
  出ます。
- ブリッジを確認します：`curl http://127.0.0.1:37421/health` が `{"ok":true,"v":1}` を
  返すはずです。失敗する場合は、ウィンドウが動いていないか、別のプロセスがポートを占有して
  います。
- ページとウィンドウは同じマシンで動かす必要があります。ブリッジはループバック専用です。
- HTTPS で配信されるページは通常、`http://127.0.0.1:37421` を混合コンテンツとしてブロック
  します。通常の `http://127.0.0.1:3080` のページを使ってください。CORS はブリッジ側で
  すでに処理されています。
- ポストが 10 秒途切れると、ウィンドウは `offline` に切り替わり、状態が戻るまでオフラインの
  シーンをアニメーションし続けます。

## デスクトップウィンドウが移動しにくい、または間違ったモニターにある

- スプライト上のどこでも左ドラッグできます。Wayland コンポジターは要求された位置を無視
  したり、移動リクエストを拒否したりすることがあります。X11 セッションを試してください。
- 右クリックメニューの**位置をリセット**で右下の既定位置に戻ります。
- デスクトップの設定は `~/.config/dsh-pixel-companions/desktop.json` に保存されます。見た目、
  位置、常に手前の状態をリセットするには、そのファイルを削除してください。

## 言語が正しくない

歯車を開き、**言語**セレクターを使います：English、Русский、中文、Tiếng Việt、日本語、
한국어。初回起動は、`navigator.language` がいずれかに一致すればそれに従い、そうでなければ
English で始まります。選択はブラウザごとで、シーンのキャプションとパネルの文言が一緒に
切り替わります。ブラウザから決まる初回起動時の言語に戻すには、
`kappy.pixel-companions.ui.v1` キーを消去してください。

## コンパニオンが 2 つ表示される

2 つの異なるプラグインが `shell.overlay`（または旧来のコンポーザー dock）に登録しています。
1 つのプロファイルで有効にするコンパニオンプラグインは 1 つだけであるべきです。
設定 → プラグインで別のペットや装飾プラグインがないか確認し、無効化してください。

## プラグイン一覧にタイトルではなくパッケージ id が表示される

ロケールのメタデータが解決されていません。インストール済みパッケージに対応する
`locale/<language>.json`（`en`、`ru`、`zh`、`vi`、`ja`、`ko`）が存在し、`meta.title` と
`meta.description` を含んでいること、そして `package.json` が `"./locale/*.json"` を
エクスポートしていることを確認してください。リンクされたチェックアウトはファイルの変更が
すぐに反映されます。取得したパッケージは再インストールが必要です。

## `client.js` の読み込みに失敗する

症状：プラグイン一覧が失敗したモジュールを報告する、またはブラウザのコンソールに
`loaded without registering "dsh-pixel-companions"` が表示される。

1. 配信されるバンドルが
   `window.__ModuleLoader__.load({ id: "dsh-pixel-companions"` で始まっていることを確認
   します。id は `package.json` のパッケージ名と等しくなければなりません。
2. パッケージがプロファイルにインストールされていることを確認します：
   `ls $DSH_HOME/profiles/web/node_modules/dsh-pixel-companions`。
3. `$DSH_HOME/profiles/web/.plugin-manager/logs/` 以下のインストールログを確認します。
4. 再インストールします：`dsh plugin --profile web remove dsh-pixel-companions` の後、
   `dsh plugin --profile web add link:"$PWD"`。

## シーンが `error` のままになる

`lastAgentError` はセッションのファクトです。失敗したターンの後、次のターンが始まるまで
セッションはそれを報告し続けます。その間ペットは `error` を表示します（ターンが止まるときに
一度だけフラッシュします）。これは意図された挙動で、ターンが成功すれば通常のシーンに
戻ります。

## 設定をリセットする

プラグインは、ドラッグした `position` を含む設定を `localStorage` の
`kappy.pixel-companions.ui.v1` に保存します。設定パネルの**位置をリセット**は位置だけを
消去します。すべての設定を既定に戻すには、ブラウザの開発者ツール（Application → Local
Storage）でそのキーを消去して再読み込みしてください。

## ブラウザのコンソールを読む

Harness は、例外を投げたプラグインコンポーネントを
`slot entry crashed in 'shell.overlay'`（コンパニオン）または
`slot entry crashed in 'conversation.input.dock'`（非表示のファクトブリッジ）として報告
します。このメッセージはコンポーネントがレンダリング中に例外を投げたことを意味し、
バンドルの読み込みに失敗したわけではありません。報告にはこのメッセージと Harness の
リリース（`dsh --version`）を含めてください。

## 完全にアンインストールする

```sh
dsh plugin --profile web remove dsh-pixel-companions
```

その後、ページを再読み込みします。プロファイルの `package.json`、ロックファイル、
バンドル一覧からパッケージが消えます。プラグインは Host の設定を一切書き込まないため、
Host 側に設定が残ることはありません。
