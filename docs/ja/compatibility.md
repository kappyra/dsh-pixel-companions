# 互換性ノート

[English](../compatibility.md) | [中文](../zh/compatibility.md) | [Русский](../ru/compatibility.md) | [Tiếng Việt](../vi/compatibility.md) | 日本語 | [한국어](../ko/compatibility.md)

このプロジェクトはソースチェックアウトの試作として始まりました。`deepseek-harness` の
クローンにコピーし、tsdown/tsc でビルドする 2 つのワークスペースパッケージです。この
リポジトリは**インストール可能な形**であり、稼働中の Harness インストールに対して検証されて
います。コンパニオンはその後、コンポーザーの dock からフレーム全体を覆うオーバーレイへ
移され、ドラッグ可能な配置、6 つの UI 言語、オプションのデスクトップウィンドウを獲得
しました。それらの変更は以下で説明し、ユーザーのウィンドウに依存する箇所にはその旨を
記します。

## 検証済み環境

| 項目 | 値 |
| --- | --- |
| Harness リリース | `0.2.2-alpha.2`（コミット `d21f653`）、インストール済み CLI、`web` プロファイル |
| ページの React | `18.3.1`（シェルのベンダーバンドル、共有モジュールテーブル） |
| 検証方法 | プラグインマネージャー経由でインストール、Client モジュールを読み込み、スロットエントリが有効 |

インストール可能なバンドルについて、実際に確認したのは次のとおりです：

- パッケージはプロファイルへインストールされ、`application: applied` を報告します。
  バンドルは `dsh.profile.bundles` に追記されます。
- バンドルは `{"id":"dsh-pixel-companions","immediately":true,...}` として、構成された
  Web のブートグラフの一部であり、`/plugins/??dsh-pixel-companions/client.js&rev=…` 経由で
  配信されるバンドルのバイト列はリポジトリの `client.js` と一致します。
- Client モジュールはモジュールローダー経由で読み込まれ、稼働中の GUI は両方のエントリが
  有効であることを一覧表示します：`shell.overlay` → `kappy-pixel-companions`（order 50）と
  `conversation.input.dock` → `kappy-pixel-companions.bridge`（order 80）。
- `node tools/build-client.mjs` はコミット済みの `client.js`（約 72 KiB）を再現し、
  `npm test` は 20 テスト——8 つのシーンルール、8 つの純粋ヘルパーテスト（`clampScale` の
  範囲処理を含む）、4 つの翻訳完全性テスト——をすべて通します。
- Harness のアセットルートは生成されたスプライト参照
  （`plugins/dsh-pixel-companions/assets/<character>/<scene>.<webp|png>?v=<sha1-8>`）を
  `200 image/webp` / `image/png` として配信します。`src/client/assets.generated.ts` は
  約 5 KiB です。
- パフォーマンス/ロジックの確認：`publishFacts` は浅く差分し、変化のないスナップショットを
  スキップします。入力はアイドルタイマーを最大 5 秒に 1 回だけ更新し、シーンを変えることは
  ありません。1 秒クロックとデスクトップのプローブ/ハートビートは、タブが隠れている間は
  停止し、表示されると再開します。回答プレビューは実行中は凍結され、停止時に一度だけ公開
  されます。レポートのピルは `role="status"` と `aria-live="polite"` を持ちます。
  ユーザーアクティビティ（下書きの入力、クリック/ドラッグ）は、シーンを変えずにアイドル
  タイマーを更新します。
- サイズ変更のパフォーマンス：両方のスライダーは `updatePrefsSoon` を通り、設定の更新を
  アニメーションフレームごとに最大 1 回へまとめます（`requestAnimationFrame`、16 ms の
  タイムアウトフォールバック）。一方、プリセットと −/+ のクリックは即座に適用されます。
  `updatePrefs` は無変化のパッチを無視します。オーバーレイは、スケール後のスプライトが
  実際にビューポートから出たときにだけ保存位置を再クランプします。シーンプレビューの
  グリッドとデスクトッププレビューのカードはメモ化され、デスクトップへのミラーリングは
  約 140 ms にデバウンスされるため、スライダーのドラッグはドラッグが落ち着いてから一度だけ
  ポストします（シーン/見た目の変更は引き続き即座にミラーリングされます）。
- シーンのマッピングは、ページとまったく同じ React バージョン（`18.3.1`）で実際のスロット
  props の形（idle、running、sending、承認待ちのインタラクション、error、オープン時の
  エラー、ツール呼び出し、推論ストリーム、回答ストリーム）に対して評価され、すべての
  ルールが期待どおりのキャプションとアートワークを生成しました。
- ヘッドレスの UI テストは完了とホバーの挙動をカバーします：入力された下書きは `Idle` の
  まま、推論ストリームは `Thinking`、回答ストリームは `Typing`、実行中のツールは
  `Working` を表示します。終了したターンは 1 行の固定レポートを表示し、その詳細ボタンが
  上限付きのプレーンテキストパネルを開きます。コンパニオンへのホバーは 320 ms の滞在時間の
  後にレポートを閉じ、新しいターンで再び開きます。ホバー時のメッセージ入力欄はメッセージ
  を送信し、以前の下書きを復元します。
- v3 のアートワークはヘッドレスで確認されました：62 のスプライトファイルすべてが透明付きの
  192×128 RGBA としてデコードされ、すべてのアニメーション WebP が少なくとも 2 フレームを
  持ちます。ヘッドレスのドラッグテストでは、Deepy がドラッグ中に `roaming` へ切り替わり、
  離すとシーンに戻ることが示されます（Whale Girl は変わりません）。
- オプションのデスクトップ側の半分はヘッドレスで確認されました：
  `python3 -m py_compile desktop/companion.py` が成功し、
  `python3 desktop/companion.py --self-test` が
  `ok: … 92 animated decodes, 31 still decodes, 30 evidence PNGs, 260 checks` を報告します
  （シーンは 0.5、1.0、2.0 のスケールでデコード）。実際の `curl` による確認は
  `/health`、CORS プリフライト、`POST /state`、`400` と `404`、同じポートでの 2 つ目の
  インスタンスが `1` で終了することをカバーします。roaming の切り替えテストも通ります
  （`whale: moving→roaming, released→idle; girl: no roaming`）。ブラウザ側のペイロードは
  ヘッドレスの React レンダーで検証され（`scene=typing` → `success`）、本文に下書きや
  セッションデータはありません。

ユーザー確認済みと記した項目（ホストのウィンドウに依存し、このリポジトリからは再検証して
いないもの）：ドラッグ/ポインター操作、すべての列の上へのオーバーレイ配置、設定パネルの
反転とクランプ、ライト/ダークの見た目、6 つの UI 言語の切り替え。これらは自分の
`dsh web` ウィンドウで確認してください。[installation.md](installation.md#verify) を
参照してください。

## 依存している API 契約

インストール済みパッケージの型宣言から確認した内容です：

| 取得元 | 用途 |
| --- | --- |
| `shell.overlay`（フレーム全体用オーバーレイスロット） | コンパニオン本体：`{ name: 'shell.overlay', id: 'kappy-pixel-companions', order: 50 }` を登録します。オーバーレイ層はクリック透過で、ポインタイベントを受け取るのはコンパニオン、その歯車ボタン、設定パネルだけです。 |
| `conversation.input.dock`（非表示のファクトブリッジ） | セッションごとの props を受け取る唯一のスロット：`{ name: 'conversation.input.dock', id: 'kappy-pixel-companions.bridge', order: 80 }` を登録します。`null` を描画し（DOM もレイアウトの隙間もなし）、ファクトの公開だけを行います。 |
| `settings.general.item`（設定 → 一般のリストスロット） | コンパニオンのサイズ行を登録します：`{ name: 'settings.general.item', id: 'pixel-companions-size', order: 40 }`。ペットのポップオーバーと同じスライダー/プリセットを描画し、共有の設定ストアを編集します。ホスト標準の一般リストスロットであり、新しい API ではありません。 |
| スロット所有者の props `{ session: SessionSnapshot, input: InputState }` | セッションのファクトとコンポーザーの状態。非表示ブリッジが受け取ります。 |
| コンパニオンのファクトストア（`src/client/bridge.ts`） | モジュールレベルの `CompanionFacts` と `publishFacts`、`useCompanionFacts`、`useFactsPublisher`、`useDisconnectOnUnmount`。スナップショットを浅く差分し、`connected` を保持します。 |
| `ReadonlyMap<SessionId, SessionStatus>` 上の `useSessionStatus(selector)` | `pendingInteraction`（承認 / 質問）。オーバーレイも購読するため、会話以外のページにいるときでも承認待ちが表示されます。 |
| `SessionSnapshot.running`、`.promptError`、`.lastAgentError`、`.openState`、`.sessionId` | 実行状態、エラー状態。 |
| `InputState.phase`（`plain` / `adjudicating` / `claimed` / `submitting` / `sending`）、`.draft` | 短い `typing` シーン用の送信フェーズ。ホバー時のメッセージ入力欄は送信後に復元するため `.draft` をスナップショットします。 |
| `useChat(selector)` → `ChatSnapshot` | アシスタントのライブな作業：`legacy.runningCalls`（ツール実行中）と、空でない `text` を持つ `legacy.partial.blocks[].kind` の `reasoning` / `text`（ストリーミング）。同じフレーム内で 1/2/4 の `live` ビットフィールドとして公開されます。 |
| `ChatSnapshot.navigation.items()[].response` | 1 行の完了プレビュー：最初の空でない行から markdown 記法を除去し、120 文字以下。閉じられるか新しいターンが始まるまでレポート行に固定され、空のときは整形済みの detail にフォールバックします。 |
| 最新の `kind === 'assistant'` を持つ `ChatSnapshot.legacy.nodes[]` と `blocks[].kind === 'text'` | 詳細パネル用の完全な確定回答テキスト。確定したアシスタントノードごとに一度抽出され、8000 文字（`MAX_DETAIL`）に制限され、`CompanionFacts.detail` として公開されます。ページ専用で、デスクトップブリッジを渡ることはありません。 |
| `inputActions.setDraft(text)` / `inputActions.submit()` | ホバー時のメッセージ入力欄がコンポーザー経由で送信し、その後ベストエフォートで以前の下書きを復元します。 |
| `localStorage` のキー `kappy.pixel-companions.ui.v1` | キャラクター、`scale`（1% 精度で 50–200%。旧来の 0.8 / 1 / 1.2 の値も受け付けてクランプ）、言語、アニメーション、表示、デスクトップの切り替え、ドラッグした `position: {x, y}`（最初のドラッグまで `null`）。ブラウザごと・プロファイルごとで、Host の設定ではありません。 |
| ページからローカルのデスクトップブリッジへの `fetch`（`src/client/desktop.ts` → `http://127.0.0.1:37421`） | オプションのデスクトップミラー：`GET /health`、`POST /state`、CORS プリフライト。新しい Harness API は使わず、デスクトップ側の半分はプラグインではなくスタンドアロンの Python プロセスです。 |
| `window.__ModuleLoader__.load({ id, factory })`、`{ inject, apply }` を返す `factory(require)` | ブラウザバンドルの形式。 |
| 共有モジュールテーブルからの `require('react')` | React。決してバンドルされません。 |
| モジュールローダーからの `require.asset(reference)` と `package.json` の `"./assets/*": "./assets/*"` | 生成されたコンテンツハッシュ付きスプライト参照をページ URL へ対応付けます。`src/client/asset-url.ts` はリゾルバーがない場合、ドキュメント相対の生の参照にフォールバックします。 |
| `$PWD/profiles/web/node_modules` のバンドル解決と `/plugins/<package>/…` の配信 | パッケージの配信。プラグインのアセットルートを含みます。 |

Chat スナップショットのフィールド、ナビゲーションの応答、コンポーザーのアクションはすでに
公開されているスロット props/フックです。サイズ行はホストの既存の `settings.general.item`
リストスロットを使い、アセットルートはモジュールローダーの既存の `require.asset` と
パッケージの `exports` マップを使います。新しい Harness API は使われておらず、15 シーンの
セットも変わっていません。

## ブリッジ → オーバーレイのデータフロー

1. 非表示の `conversation.input.dock` エントリ（`src/client/Pet.tsx` の
   `CompanionBridge`、`src/client/bridge.ts` を使用）が、現在の `SessionSnapshot`、
   `InputState`、Chat スナップショット（ライブビット、回答プレビュー、最新の確定アシスタント
   ノード）、`useSessionStatus` の承認待ちフラグ、コンポーザーのアクションを受け取ります。
2. それらをモジュールレベルのコンパニオンファクトストアへマージし、購読者へ通知します。
   ファクトには実行の開始/停止のタイムスタンプ、`live` ビットフィールド（1 = ツール、
   2 = 推論、4 = 回答）、1 行の `report`、完全な `detail` が含まれます。ライブビットは
   Chat スナップショットと同じフレーム内で更新され、`report`/`detail` はターン実行中は
   凍結されて停止時に一度だけ公開されます。
3. `shell.overlay` コンポーネント（`Companion`）は `useCompanionFacts()` を通じてストアを
   読み、あわせて `useSessionStatus` も購読し、`src/client/state.ts` の `deriveScene` で
   シーンを導出します。
4. 会話がアンマウントされると、ブリッジは `connected: false` を `running: false` とともに
   公開し、最後のファクトを保持します。オーバーレイは、どのセッションも公開していない
   実行状態を主張する代わりに、待機/休眠の挙動へフォールバックします。
5. シーンの選択のためにプロンプトのテキストが読まれることはなく、モデル呼び出しも行われ
   ません。下書きがスナップショットされるのは、ホバー時のメッセージ入力欄がコンポーザー
   経由で送信した後にそれを復元できるようにするためだけです。
6. 完了は固定表示です。`success` とレポート行は、ユーザーがコンパニオンにホバーする
   （320 ms の滞在時間）か新しいターンが始まるまで残り、ナビゲーションのプレビューが空の
   ときはレポートが整形済みの `detail` にフォールバックします。詳細ボタンは、完全な回答を
   React でエスケープしたプレーンテキスト（改行を保持し、8000 文字に制限）として表示する
   ビューポートクランプ付きの `role="dialog"` を開きます。閉じるには ✕、Escape、外側の
   クリックを使います。レポートのテキストは `role="status"` / `aria-live="polite"` を保ち、
   ボタンは `aria-expanded` を公開します。

## 6 言語の辞書

UI の文言はすべて Host のロケールファイルではなく `src/client/text.ts` にあります：

- `LANGUAGES` — 6 つの言語とその表示ラベル：English、Русский、中文、Tiếng Việt、
  日本語、한국어。
- `languageFromTag(tag)` — BCP 47 タグ（たとえば `navigator.language`）を言語 id に解決し、
  既定では English を返します。
- `SCENE_LABELS` — 6 言語すべてにおけるシーンごとのキャプション。
- `UI_TEXT` — 位置をリセット、閉じる、ホバー時の入力欄のプレースホルダーと送信の操作を
  含む、設定とメッセージ入力欄のすべてのラベル。

`locale/*.json` は設定 → プラグインに表示されるプラグインインベントリのメタデータ
（`meta.title` / `meta.description`）のままで、同じ 6 言語をカバーするようになりました。
シーンのキャプションと UI の文言は 6 言語すべてで自然かつ正確な表現に改められ、インベントリ
のタイトル/説明も同様に書き直されました。翻訳の完全性は `tests/text.test.ts` でカバーされて
います。

## プロトタイプからの変更点

1. **2 つのワークスペースパッケージではなく、1 つのインストール可能なパッケージ。**
   `-ui` と `-bundle` の分割は DSH のソースチェックアウト内でしか意味を持ちません。
   `cordis.patch.yml`、`index.js`、`package.json`（`dsh.bundle` + `dsh.client`）、ロケール
   メタデータはリポジトリのルートにあります。
2. **コミット済みクライアントバンドルのための依存なしビルド。** `tools/build-assets.mjs`
   はコンテンツハッシュ付きのアセットルート参照を書き出し、`tools/build-client.mjs` は
   TypeScript を esbuild でバンドルし、`react` を external に保ち、結果をモジュール
   ローダーの登録で包みます。生成された `client.js` はコミットされるため、インストールに
   ツールチェーンは不要です。
3. **本物のテーマトークン。** `--dsw-alias-border-l3` と `--dsw-specific-input-major` は
   出荷されるトークンではありません。プラグインは `--dsw-alias-border-l2`、
   `--dsw-alias-bg-layer-1`、`--dsw-alias-bg-overlay`、`--dsw-alias-brand-primary` を使い、
   それぞれにリテラルのフォールバックを付けているため、オーバーレイとそのパネルは
   ハードコードされた暗いパレットではなくホストのテーマに従います。
4. **コンポーザー dock の見た目ではなく、フレーム全体を覆うオーバーレイ。** コンパニオンは
   `shell.overlay`（すべての列の上、すべてのページ）へ移りました。非表示のファクトブリッジ
   だけが `conversation.input.dock` に残るため、コンポーザーにレイアウトの隙間は追加され
   ません。
5. **クリック透過のオーバーレイ層。** オーバーレイ層は `pointer-events: none` です。ポインタ
   入力を受け付けるのはコンパニオン、その歯車、パネルだけなので、ページの他の部分はこれまで
   どおりスクロールや選択ができます。
6. **どこへでもドラッグできる配置。** 小さなドラッグしきい値がドラッグとクリックを区別
   します。位置はビューポート内にクランプされ、リサイズ時に再クランプされ、
   `kappy.pixel-companions.ui.v1` に `position: {x, y}` として保存されます（最初のドラッグ
   までは `null` なので、それまでは自動の右下既定位置がリサイズに追随し続けます）。
7. **6 つの UI 言語。** `src/client/text.ts` が辞書と `languageFromTag` を保持し、初回起動は
   `navigator.language` に従い、そうでなければ English です。設定パネルはライブで言語を
   切り替えます。
8. **プラグインインベントリのメタデータ。** `locale/en.json`、`locale/ru.json`、
   `locale/zh.json`、`locale/ja.json`、そして新しい `locale/vi.json` / `locale/ko.json` が
   `meta.title` / `meta.description` を持ち、`icon.svg` がエクスポートされるため、
   設定 → プラグイン一覧はパッケージ id ではなく名前でプラグインを表示します。
9. **ソースチェックアウト用インストーラーの削除。** `install-to-dsh.sh` と
   `packages/experimental/**` ツリーは削除されました。文書化された経路はプロファイル
   バンドルです。
10. **オプションのデスクトップウィンドウ。** `desktop/companion.py` は同じスプライトを
    フレームなし・常に手前・ピクセル単位で透明な GTK 3 ウィンドウに描画し、ループバック
    専用の HTTP ブリッジ（`src/client/desktop.ts`）経由でページから表示状態を受け取ります。
    既定ではオフで、プロンプト/下書き/メッセージ/セッションのデータを持たず、新しい
    Harness API も必要としません。
11. **v3 のアートワークと roaming の移動ビジュアル。** `assets/` には 30 の少女 + 30 の
    クジラのスプライト（各 15 シーン）と、オプションの `assets/whale/roaming.{webp,png}` の
    組が入っています。Deepy がドラッグされている間——オーバーレイでもデスクトップ
    ウィンドウでも——机のない `roaming` アニメーションがシーンに代わり、固定された家具が
    移動しないようにします。離すとシーンが戻ります。`roaming` はシーンではありません。
    15 状態のステートマシン、`deriveScene`、ブリッジのペイロード、デスクトップのプロトコルは
    変わらず、Harness API も追加されていません。
12. **ライブ状態、ホバー時のメッセージ入力欄、固定表示の完了、詳細。** シーンはアシスタント
    自身の作業——実行中のツール呼び出し、ストリーミング中の推論、ストリーミング中の回答
    テキスト、またはライブストリームのない実行中のターン——に追随するようになりました。
    そのため `thinking` がユーザーの下書き入力でトリガーされることはありません。終了した
    ターンは固定表示です。`success` と 1 行レポート、そしてローカライズされた**詳細**ボタン
    が、ユーザーがコンパニオンにホバーするか新しいターンが始まるまで残ります。ホバーすると
    これらは閉じ、詳細は完全な回答を上限付きのプレーンテキストとして開きます。コンパニオンは
    1 行の入力欄も備え、コンポーザー経由で送信して以前の下書きを復元します。レポートと
    ホバー時のメッセージ入力欄は 1 つのビューポートクランプ列を共有し、完了が閉じられるまで
    入力欄はレポートの直下にあります。これらは既存の Chat スナップショット、コンポーザーの
    アクション、`useSessionStatus` の props を使います。Harness API は変わらず、15 シーンの
    セットも変わりません。シーンのキャプションと UI の文言は 6 言語すべてで改訂されました。
13. **アセットルート配信とパフォーマンスの改善。** スプライトはもう埋め込まれません。
    マニフェストは Harness のアセットルートが配信する
    `plugins/dsh-pixel-companions/assets/...?v=<sha1-8>` 参照を保持し、`require.asset` 経由で
    解決され、生の参照へのフォールバックがあります。コミット済みの `client.js` は約 3.3 MB
    から約 72 KiB に減りました。スプライトはシーンごとに取得され、不変としてキャッシュされ、
    コンテンツハッシュがキャッシュを更新します。ブリッジはファクトを浅く差分し、1 秒クロック
    とデスクトップのプローブ/ハートビートは隠れたタブで停止し、回答プレビューは停止時に一度
    だけ公開され、ユーザーアクティビティはシーンを変えずにアイドルタイマーを更新し（入力は
    5 秒に 1 回にスロットリング）、レポートのピルは `role="status"` /
    `aria-live="polite"` で通知されます。Harness API は追加されず、15 シーンのセット、
    シーンルール、ホバー入力欄、レポート、デスクトップブリッジ、デスクトップアプリは
    変わりません。
14. **コンパニオンサイズの連続調整。** ブラウザのサイズ行は 50–200% のレンジスライダーで、
    5% 刻み、−/+ ボタン、リアルタイムのパーセント表示、50/100/150/200% のプリセットチップ
    付きです（有効なプリセットは `aria-pressed` で示され、微調整用にスライダーも残ります）。
    スプライトは実際のスケール後のピクセルサイズ（100% で 152×98、50% で 76×49、200% で
    304×196）で描画されるため、ヒットエリア、キャプションと歯車、ビューポートのクランプ、
    レポート/入力の列のアンカー、詳細パネルもそれに追随します。保存値は 1% 精度を受け付け、
    読み込み時に 50–200 にクランプされます。旧来の 0.8 / 1 / 1.2 の値も引き続き動作し、
    スライダーの変更は 180 ms のデバウンスで永続化され、アンマウント時にフラッシュされます。
    デスクトップアプリは `--scale` を 0.5 から 2.0 まで（1% に丸め）受け付け、そのサイズ
    メニューは 50 / 75 / 100 / 125 / 150 / 200% を提供します。同じサイズ操作はホストの
    設定 → 一般リスト（`settings.general.item`、id `pixel-companions-size`、order 40）にも
    登録され、ローカライズされた**コンパニオンの大きさ**のタイトルと説明を持ちます。
    どちらの画面も共有のクライアントローカル設定ストア（`src/client/prefs.ts`、
    `usePrefs` / `updatePrefs`）を使うため、一方の変更がもう一方を即座に更新し、同じ
    `localStorage` キーへ 180 ms のデバウンスと `pagehide` 時のフラッシュ付きで永続化
    されます。新しい Harness API もプロトコルやシーンの変更もありません。

## 既知の制限

- コミット済みの JS バンドルは約 72 KiB です。62 のスプライトファイル（少女 30 + クジラ 32、
  オプションの roaming の組を含む）はプラグインのアセットルートから別途配信され、不変として
  キャッシュされます。`?v=<sha1-8>` はファイルが変わったときにキャッシュを更新します。これに
  より起動は安く済みますが、`assets/` ツリーはパッケージと一緒に配布する必要があります。
- シーンのマッピングは「完了」と「停止/キャンセル」を区別できません。クライアントは現在
  `running` をブール値として公開しています。そのため `success` シーンは「エラーなしで
  停止した」を意味します。
- 承認待ちが他のページでも見えるのは、オーバーレイ自身が `useSessionStatus` を購読して
  いるからだけです。ファクトブリッジは会話の外ではアンマウントされ、保持されたファクトには
  `connected: false` が付きます。
- 完了は時間制ではなく固定表示です。レポート行と `success` シーンは、ユーザーがコンパニオン
  にホバーする（320 ms の滞在）か新しいターンが始まるまで残ります。レポート行自体にホバー
  しても閉じません。回答が空なら何も表示されず、**詳細**ボタンは確定したアシスタントノードが
  テキストを提供したときにだけ現れます。パネルはプレーンテキストのみを描画し、8000 文字に
  制限されます。`detail` はページ内にとどまり、デスクトップブリッジを渡ることはありません。
  ホバー時のメッセージ入力欄はマウントされた会話を必要とし、以前の下書きをベストエフォート
  で復元します。送信の受け付け中にコンポーザーがロックされていると、その下書きは失われる
  ことがあります。
- デスクトップウィンドウはグラフィカルセッションなしでは検証できません。実際のウィンドウ、
  Cairo ブリッジがない場合のピクセル単位の透明化（不透明なフォールバックが想定されます）、
  常に手前/ドラッグ/メニューの描画、Wayland の配置はここでは未検証です。ブリッジはページを
  開いたままにし、両方の半分を同じホストで動かす必要があります。認証のないループバック通信
  なので、ポートを公開してはいけません。
- HTTPS で配信されるページは通常、ループバックブリッジを混合コンテンツとしてブロックします。
  通常の `http://127.0.0.1:3080` のページを使ってください。
- 両方のスロット画面は React のエラーバウンダリーで包まれています。レンダリングに失敗すると
  `[dsh-pixel-companions] surface failed` をログに記録し、スロットエントリをクラッシュ
  させる代わりに何も描画しないため、Harness UI の残りは動作し続けます。
- オプションのデスクトップブリッジは、プローブする前に `fetch` の存在を確認します。
  それがないブラウザは例外を投げずに**未起動**を報告します。
- コンパニオンは Web クライアントが公開するものに反応します。`SessionSnapshot`、
  `InputState`、`shell.overlay`、またはスロット登録の形を変更する Host には、ここでの
  対応する更新が必要です。スロット、props、モジュール形式は公開プラグイン API なので、
  破綻は Harness UI ではなくプラグイン自身のコードに見えます。
