# 문제 해결

[English](../troubleshooting.md) | [中文](../zh/troubleshooting.md) | [Русский](../ru/troubleshooting.md) | [Tiếng Việt](../vi/troubleshooting.md) | [日本語](../ja/troubleshooting.md) | 한국어

## 컴패니언이 보이지 않음

1. **번들이 활성화되어 있나요?** 설정 → 플러그인 → 플러그인 목록. 항목 이름은
   *Pixel companions*입니다. `disabled`로 표시되면 활성화하세요.
2. **숨겨져 있나요?** 설정 패널에 **표시** 스위치가 있습니다. 꺼져 있으면 컴패니언
   위치에 작은 🐳 버튼만 남습니다. 그것을 클릭하면 컴패니언이 돌아옵니다.
3. **페이지를 새로고침하세요.** 새로 설치한 번들은 보통 1~2초 안에 핫스왑되지만
   새로고침이 항상 안전합니다. 컴패니언은 프레임 전체 오버레이에 렌더링되므로 열린
   대화가 필요하지 않습니다. 설정과 플러그인을 포함한 모든 페이지에 나타납니다.
4. **Host를 재시작하세요.** `dsh web` 프로세스에서 `Ctrl+C`를 누르고 다시 시작합니다.
   `package.json` 변경(예: 버전 올리기)에는 재시작이 필요합니다.
5. **프로필을 확인하세요.** `dsh --profile web --dump-config`에
   `dsh-pixel-companions`라는 행이 있어야 합니다. 없다면 번들이 등록되지 않은 것이므로
   `dsh plugin --profile web add link:"$PWD"`를 다시 실행하세요.

## 컴패니언은 보이지만 멈춤

- 설정 패널에서 **애니메이션**이 꺼져 있거나 OS가 동작 줄이기를 요청한 경우
  (`prefers-reduced-motion: reduce`)입니다. 둘 다 설계상 정적 PNG를 그립니다.
- 장면 자체가 정적처럼 보이는 장면(`sleeping`, `waiting`)일 수 있습니다. 스프라이트 위의
  캡션을 확인하세요.

## 드래그해도 컴패니언이 움직이지 않음

- 주변의 빈 공간이 아니라 **스프라이트 자체**(컴패니언이 숨겨져 있으면 🐳 버튼)를
  드래그하세요. 오버레이 레이어는 설계상 클릭 통과입니다.
- 놓기 전에 3픽셀 드래그 임계값보다 더 움직이세요. 더 짧은 누름은 클릭으로 처리되어 대신
  설정 패널을 엽니다.
- 마우스, 터치, 펜 모두 동작하며, 보조 마우스 버튼은 드래그를 시작하지 않습니다.
- 위치가 오래되었거나 포인터가 멈춘 것 같으면 톱니바퀴를 열고 **위치 초기화**를 선택한 뒤
  다시 시도하세요.

## 컴패니언이 너무 크거나 작음

**설정 → 일반 → 컴패니언 크기** 또는 컴패니언의 ⚙ 팝오버를 엽니다. 둘 다 같은 컨트롤을
보여 주고 같은 환경설정을 편집합니다. 가장 빠른 방법은 크기 행 아래의
**50/100/150/200%** 프리셋 칩을 누르는 것이고, 미세 조정은 **크기** 슬라이더(50–200%,
5% 단위, −/+ 버튼과 실시간 퍼센트)를 사용합니다. 스프라이트는 실제 확대 픽셀 크기로
렌더링되므로 클릭 영역, 캡션/톱니바퀴, 보고서/입력 열, 세부 정보 패널이 이를 따릅니다.
크기가 바뀌면 저장된 위치가 자동으로 다시 제한되며, 컴패니언이 어색한 곳에 있으면
**위치 초기화**가 자동 오른쪽 아래 위치를 복원합니다. 두 컨트롤이 모두 보이지 않으면 페이지가
오래된 클라이언트 번들을 실행 중이므로 강제 새로고침하세요(번들을 방금 업데이트했다면
`dsh web`도 재시작).

## 호버 메시지 입력창이 나타나지 않음

한 줄 입력창은 대화가 마운트되어 있고, 입력창을 사용할 수 있으며, 컴패니언이 보일 때만
컴패니언 위에 마우스를 올리면 열립니다. 컴패니언을 드래그하는 동안이나 설정 패널이 열려
있으면 숨겨지고, 터치 기기에서는 열리지 않습니다. 포인터를 스프라이트 위로 옮겨 유지하세요.
입력창은 컴패니언 아래(또는 위)에 표시되고 뷰포트 안으로 제한됩니다. 완료 보고서가 보이는
동안에는 입력창이 같은 제한 열의 보고서 바로 아래에 있습니다. 보고서에 호버하면 입력창이
드러나고 보고서는 열린 채로 유지되며, 보고서 행과 그 **자세히** 버튼 자체는 메시지 입력창을
열지 않습니다. 스프라이트에 호버하면 고정 완료 상태를 닫는 320 ms 대기가 시작되고, 닫힌
뒤에는 입력창이 컴패니언 아래로 돌아갑니다. 보고서에서 벗어나면 입력창이 다시 숨겨지고
보고서는 스프라이트에 호버하거나 새 턴이 시작될 때까지 유지됩니다.

## 메시지 입력창이 초안을 삼킴

메시지 입력창은 입력창을 통해 전송하고(`setDraft` + `submit`), 메시지를 큐에 넣은 직후
이전 입력창 초안을 복원합니다. 그 순간 입력창이 제출 또는 승인 단계로 잠겨 있으면 복원이
실패해 초안을 잃을 수 있습니다. 빈 초안은 그대로 비어 있습니다. 필요하면 초안을 다시
입력하세요. 메시지 입력창에서 보내는 것은 세션 기록을 바꾸지 않습니다.

## 완료 보고서가 보이지 않음

보고서는 고정됩니다. 성공한 턴 뒤에 한 줄 미리보기(첫 번째 비어 있지 않은 줄, ≤ 120자,
markdown 기호 제거)가 컴패니언에 호버하거나 새 턴이 시작될 때까지 유지됩니다. 320 ms 호버
대기로 닫히며, 보고서 행 자체에 호버해도 닫히지 않습니다. 한 번 닫히면 다음 완료 턴이 다시
엽니다. 답변이 비어 있으면 아무것도 표시되지 않고, **자세히** 버튼은 확정된 어시스턴트
답변이 텍스트를 제공했을 때만 나타납니다. 버튼이 있으면 전체 답변을 길이 제한된 일반
텍스트로 엽니다.

## 모니터나 창 크기를 바꾼 뒤 컴패니언이 화면 밖에 있음

위치는 뷰포트에 맞게 제한되고 크기 변경 시 다시 제한되지만, 저장된 위치는 모니터 변경,
확대/축소 변경, 매우 작은 창 이후에도 어색할 수 있습니다. 톱니바퀴를 열고 **위치 초기화**를
선택하면 컴패니언이 자동 오른쪽 아래 위치로 돌아가고 다시 창 크기 변경을 따라갑니다.
`localStorage`의 `position` 필드를 지워도 같은 효과가 있습니다.

## 설정 패널이 잘리거나 화면 밖에서 열림

패널은 컴패니언에 고정되고 사용 가능한 공간에 따라 위나 아래로 전환되며 뷰포트 안으로
제한됩니다:

- 컴패니언이 구석에 있으면 패널을 열기 전에 가운데로 드래그하세요.
- **위치 초기화**는 기본 위치로 돌려놓습니다.
- 비정상적으로 작은 창에서는 패널이 스크롤됩니다. 창 크기를 조절하거나 계속 사용할 수
  없다면 크기를 알려 주세요.

## 에셋 변경 후 스프라이트가 오래되었거나 404 발생

스프라이트 URL에는 콘텐츠 해시(`?v=<sha1-8>`)가 포함되고 매니페스트는 빌드 시 생성됩니다.
`assets/` 아래 파일을 교체한 뒤 `npm run build`를 실행해
`src/client/assets.generated.ts`와 `client.js`를 다시 생성하고 페이지를 새로고침하세요.
그래도 오래된 에셋이 보이면 캐시된 문서를 버리도록 강제 새로고침하세요. 404는 설치된
패키지에 `assets/` 트리가 더 이상 없다는 뜻이므로 번들을 다시 설치하세요.

## 데스크톱 창이 열리지 않음

데스크톱 앱은 번들의 일부가 아닌 별도 Python 프로세스입니다. 체크아웃에서
`python3 desktop/companion.py`(또는 `./desktop/run.sh`)로 시작하세요.

- **디스플레이 없음.** 창에는 X11 또는 Wayland가 필요합니다. 서버에서는 `ssh -X`,
  XWayland가 있는 Wayland 세션, 가상 디스플레이를 사용하세요. 순수 WSL 호스트에는 X
  서버가 필요합니다. 화면이 필요 없는 부분은
  `python3 desktop/companion.py --self-test`로 확인하세요.
- **포트 사용 중.** `cannot listen on 127.0.0.1:37421`은 다른 컴패니언 인스턴스가 실행
  중이라는 뜻입니다. 종료하세요. 페이지가 항상 37421을 확인하므로 기본 포트를 유지하는
  것이 가장 간단합니다.
- **GTK 또는 Pillow 누락.** 스크립트가 PyGObject/GTK 메시지나 Pillow `ImportError`로
  종료됩니다. `python3-gi gir1.2-gtk-3.0`를 설치하고
  `python3 -m pip install --user Pillow`를 실행하세요.

## 데스크톱 창이 불투명한 어두운 상자로 보임

Cairo 바인딩이나 합성 창 관리자가 없으면 창은 설계상 스프라이트를 단색 어두운 배경에
그립니다. `python3-cairo`를 설치하고 합성 WM/세션을 사용한 뒤 창을 재시작하세요.

## 데스크톱 창이 계속 `offline` 상태임

- 페이지가 열려 있어야 하고 톱니바퀴 패널에서 **데스크톱 창**이 체크되어 있어야 합니다. 행은
  **꺼짐**, **실행 중이 아님**, **연결됨**을 표시합니다. 켜져 있으면 행 아래 미리보기 카드가
  같은 상태를 반복하고 시작 명령을 알려 주며, 행에 호버해도 같은 힌트가 나옵니다.
- 브리지를 확인하세요. `curl http://127.0.0.1:37421/health`가
  `{"ok":true,"v":1}`을 반환해야 합니다. 실패하면 창이 실행 중이 아니거나 다른 프로세스가
  포트를 차지하고 있습니다.
- 페이지와 창은 같은 머신에서 실행되어야 합니다. 브리지는 루프백 전용입니다.
- HTTPS로 제공되는 페이지는 보통 `http://127.0.0.1:37421`을 혼합 콘텐츠로 차단합니다.
  일반적인 `http://127.0.0.1:3080` 페이지를 사용하세요. CORS는 브리지가 이미 처리합니다.
- 창은 게시가 10초 없으면 `offline`으로 전환되고 상태가 돌아올 때까지 오프라인 장면
  애니메이션을 계속 재생합니다.

## 데스크톱 창을 옮기기 어렵거나 잘못된 모니터에 있음

- 스프라이트 위 아무 곳이나 왼쪽 드래그하세요. Wayland 합성기는 요청한 위치를 무시하거나
  이동 요청을 거부할 수 있습니다. X11 세션을 시도하세요.
- 오른쪽 클릭 메뉴의 **위치 초기화**는 오른쪽 아래 기본 위치로 돌려놓습니다.
- 데스크톱 환경설정은 `~/.config/dsh-pixel-companions/desktop.json`에 저장됩니다. 그 파일을
  삭제하면 외형, 위치, 항상 위 상태가 초기화됩니다.

## 언어가 잘못됨

톱니바퀴를 열고 **언어** 선택기를 사용하세요: English, Русский, 中文, Tiếng Việt,
日本語, 한국어. 첫 실행은 `navigator.language`가 그중 하나와 일치하면 그것을 따르고,
아니면 영어로 시작합니다. 선택은 브라우저 단위이며 장면 캡션과 패널 문구가 함께
전환됩니다. 브라우저에서 추론한 첫 실행 언어로 돌아가려면
`kappy.pixel-companions.ui.v1` 키를 지우세요.

## 컴패니언이 두 개 나타남

두 개의 다른 플러그인이 `shell.overlay`(또는 이전 입력창 dock)에 등록하고 있습니다. 한
프로필에서는 컴패니언 플러그인 하나만 활성화해야 합니다. 설정 → 플러그인에서 다른 펫이나
장식 플러그인이 있는지 확인하고 비활성화하세요.

## 플러그인 목록에 제목 대신 패키지 id가 표시됨

locale 메타데이터가 해석되지 않았습니다. 설치된 패키지에 해당
`locale/<language>.json`(`en`, `ru`, `zh`, `vi`, `ja`, `ko`)이 있고
`meta.title`과 `meta.description`을 포함하는지, `package.json`이
`"./locale/*.json"`을 내보내는지 확인하세요. 링크된 체크아웃은 파일 변경이 즉시 보이지만,
가져온 패키지는 재설치가 필요합니다.

## `client.js`를 불러오지 못함

증상: 플러그인 목록이 실패한 모듈을 보고하거나 브라우저 콘솔에
`loaded without registering "dsh-pixel-companions"`가 표시됩니다.

1. 제공된 번들이
   `window.__ModuleLoader__.load({ id: "dsh-pixel-companions"`로 시작하는지 확인하세요.
   id는 `package.json`의 패키지 이름과 같아야 합니다.
2. 패키지가 프로필에 설치되어 있는지 확인하세요:
   `ls $DSH_HOME/profiles/web/node_modules/dsh-pixel-companions`.
3. `$DSH_HOME/profiles/web/.plugin-manager/logs/` 아래 설치 로그를 확인하세요.
4. 다시 설치하세요: `dsh plugin --profile web remove dsh-pixel-companions` 후
   `dsh plugin --profile web add link:"$PWD"`.

## 장면이 계속 `error`에 머묾

`lastAgentError`는 세션 사실입니다. 실패한 턴 뒤에는 다음 턴이 시작될 때까지 세션이 계속
그것을 보고합니다. 그동안 pet은 `error`를 표시하며, 턴이 정지할 때 일회성 플래시가
나타납니다. 이는 의도된 동작이며, 성공한 턴이 정상 장면으로 돌려놓습니다.

## 환경설정 초기화

플러그인은 드래그한 `position`을 포함한 설정을 `localStorage`의
`kappy.pixel-companions.ui.v1`에 저장합니다. 설정 패널의 **위치 초기화**는 위치만 지웁니다.
모든 환경설정을 기본값으로 돌리려면 브라우저 개발자 도구(Application → Local Storage)에서
그 키를 지우고 새로고침하세요.

## 브라우저 콘솔 읽기

Harness는 예외를 던진 플러그인 컴포넌트를
`slot entry crashed in 'shell.overlay'`(컴패니언) 또는
`slot entry crashed in 'conversation.input.dock'`(숨겨진 사실 브리지)로 보고합니다. 이
메시지는 컴포넌트가 렌더 중에 예외를 던졌다는 뜻이며 번들 로드 실패가 아닙니다. 보고할 때
이 메시지와 Harness 릴리스(`dsh --version`)를 함께 포함하세요.

## 완전히 제거

```sh
dsh plugin --profile web remove dsh-pixel-companions
```

그다음 페이지를 새로고침하세요. 프로필의 `package.json`, lockfile, 번들 목록에서 패키지가
사라집니다. 플러그인은 아무것도 쓰지 않으므로 남는 Host 설정도 없습니다.
