# 데스크톱 창

[English](../desktop.md) | [中文](../zh/desktop.md) | [Русский](../ru/desktop.md) | [Tiếng Việt](../vi/desktop.md) | [日本語](../ja/desktop.md) | 한국어

`desktop/companion.py`는 같은 픽셀 컴패니언을 브라우저 밖에 보여 주는 **선택적 독립
데스크톱 창**입니다. 프레임이 없고 항상 위에 있으며 픽셀 단위로 투명하고, 마우스 왼쪽
버튼으로 드래그할 수 있으며 오른쪽 클릭 메뉴가 있습니다. GTK 3(PyGObject)와 Pillow, 아주
작은 localhost HTTP 브리지로 구성된 순수 Python 3 프로그램이며, Harness 플러그인이 아니고
웹 GUI도 바꾸지 않습니다.

창은 스프라이트이고, 웹 페이지가 두뇌입니다. 브라우저 절반은 일반 번들의 일부이며
컴패니언 설정 패널에서 **데스크톱 창**을 켜기 전까지 유휴 상태로 있습니다. 기본값은
꺼짐이므로 데스크톱 앱이 없는 페이지는 로컬 포트를 전혀 확인하지 않습니다. 두 절반은 같은
머신에서 실행되어야 합니다. 브리지는 `127.0.0.1`에만 바인딩되고 인증이 없습니다.

상태는 이제 어시스턴트 자체의 작업 — 실행 중인 도구 호출, 스트리밍 중인 추론이나 답변
텍스트, 또는 왕복 중인 요청 — 을 따르며, 데스크톱 미러도 같은 장면을 보여 줍니다.
브리지 프로토콜은 바뀌지 않았습니다. 브라우저는 완료된 턴의 `success` 장면과 보고서를
고정으로 유지하므로, 페이지가 유지하는 동안 데스크톱 창은 `success`를 미러링합니다. 보고서
행과 세부 정보 패널은 브라우저 전용입니다.

## 요구 사항

- 브라우저 페이지와 같은 머신의 Python 3.10+.
- PyGObject, Cairo 바인딩, Pillow가 포함된 GTK 3:

```sh
sudo apt install python3-gi gir1.2-gtk-3.0 python3-cairo
python3 -m pip install --user Pillow
```

`python3-cairo`가 창을 픽셀 단위로 투명하게 만드는 요소입니다. 이것이 없거나 합성 창
관리자가 없으면 창은 여전히 실행되지만 스프라이트를 단색 어두운 배경에 그립니다.
`desktop/requirements.txt`에는 pip용 `PyGObject>=3.42`와 `Pillow>=10`이 나열되어 있으며,
PyGObject는 보통 pip가 아니라 배포판에서 제공됩니다.

스프라이트 프레임은 저장소의 `assets/` 디렉터리(`assets/girl/`, `assets/whale/`)에서
가져오며, 체크아웃에서는 추가 다운로드가 필요 없습니다.

## 실행

저장소 루트에서:

```sh
python3 desktop/companion.py
# or
./desktop/run.sh
```

| 플래그 | 의미 |
| --- | --- |
| `--port PORT` | 브리지 포트, 기본 `37421`. 이 버전의 페이지는 항상 `37421`을 확인하므로 기본값을 유지하세요. |
| `--assets DIR` | 에셋 디렉터리. 기본값은 저장소의 `assets/`입니다. |
| `--scale 0.5\|…\|2.0` | 초기 스프라이트 배율. `0.5`에서 `2.0` 사이의 임의 값(1%로 반올림)이며, 범위를 벗어나면 사용법 오류로 종료합니다. 이후에는 오른쪽 클릭 메뉴가 외형을 관리합니다. |
| `--no-animation` | 애니메이션 WebP 대신 정적 PNG로 시작합니다. |
| `--lang en\|ru\|zh\|vi\|ja\|ko` | 예약됨. 창은 텍스트를 그리지 않으므로 시각적으로 아무것도 바뀌지 않습니다. |
| `--stale-ms MS` | 만료 창(밀리초). 테스트 훅이며 기본값은 `10000`입니다. |
| `--self-test` | 헤드리스 인수 테스트를 실행하고 종료합니다. 디스플레이가 필요 없습니다. |

창은 페이지가 첫 상태를 보낼 때까지 `offline`으로 시작합니다. 환경설정(외형, 위치, 항상
위)은 `~/.config/dsh-pixel-companions/desktop.json`에 저장됩니다:

```json
{"character": "girl", "scale": 1, "animation": true, "alwaysOnTop": true, "x": 1200, "y": 600}
```

첫 실행 시 그 파일에 저장된 캐릭터가 없으면 첫 브라우저 페이로드가 캐릭터를 선택할 수
있습니다. 그 이후에는 메뉴가 권위를 가지며 페이로드는 장면만 구동합니다. 저장된 `scale`은
`0.5`에서 `2.0` 사이의 임의 값(1%로 반올림)을 허용하며, 레거시 `0.8` / `1` / `1.2` 값도
계속 로드됩니다.

## 브라우저 측 활성화

1. **설정 → 플러그인**에서 번들이 활성화되어 있고 웹 페이지가 열려 있는지 확인합니다
   (보통 `http://127.0.0.1:3080`).
2. 데스크톱 창을 시작합니다(나중에 시작해도 됩니다. 페이지는 10초마다 다시 확인합니다).
3. 컴패니언의 톱니바퀴 패널을 열고 **데스크톱 창**을 체크합니다.

행은 현재 상태를 표시합니다:

| 상태 | 의미 |
| --- | --- |
| **꺼짐** | 비활성화됨. 페이지가 데스크톱 포트를 전혀 확인하지 않습니다. |
| **실행 중이 아님** | 활성화되었지만 `127.0.0.1:37421`에서 응답이 없습니다. |
| **연결됨** | 데스크톱 창이 마지막 확인에 응답했고 장면이 미러링 중입니다. |

**데스크톱 창**이 켜져 있으면 행 바로 아래에 미리보기 카드가 나타납니다. 체커보드 배경의
무대가 현재 스프라이트를 데스크톱 창이 렌더링할 방식 그대로(같은 캐릭터, 장면, 모션 상태,
픽셀화 배율) 보여 주며 제목은 **데스크톱 창 미리보기**입니다. 녹색 **연결됨** 또는
호박색 **⚠ 실행 중 아님 — `desktop/companion.py`를 실행하세요**를 표시합니다. 카드는
표시 전용이며 버튼도 프로토콜 변경도 없고, 옵션이 꺼지면 사라집니다. 행에 호버해도 시작
힌트가 표시됩니다.

활성화되어 연결된 동안 페이지는 10초마다 `GET /health`를 확인하고, 장면이나 외형이 바뀌면
상태를 게시하며 4초 하트비트를 보냅니다. 창은 게시 후 약 120 ms 안에 변경을 반영합니다.
실시간 상태를 위해서는 페이지를 열어 두세요. 10초 넘게 상태가 도착하지 않으면(페이지
종료, 새로고침, 네트워크 차단) 창은 `offline`을 표시하고 계속 실행합니다.

## 오른쪽 클릭 메뉴

- **캐릭터** — Lumi(`girl`) 또는 Deepy(`whale`).
- **애니메이션** — 애니메이션 WebP 또는 정적 PNG.
- **크기** — 50%, 75%, 100%, 125%, 150%, 200%.
- **항상 위** — 창의 항상 위 힌트를 토글합니다.
- **위치 초기화** — 오른쪽 아래 기본 위치로 돌아갑니다.
- **1시간 숨기기** — 창을 숨기고 1시간 뒤 자동으로 다시 나타납니다.
- **종료** — 환경설정을 저장하고 종료합니다.

스프라이트 위 아무 곳이나 왼쪽 드래그하면 창이 움직이고 위치가 저장됩니다. 창을 옮기는
동안 Deepy는 책상이 없는 `roaming` 애니메이션으로 전환되고 놓으면 미러링된 장면으로
돌아옵니다. Whale Girl은 장면 스프라이트를 유지합니다. 이는 이동 비주얼일 뿐이며 브리지
프로토콜과 15개 장면 집합은 바뀌지 않았습니다. 창은 프레임이 없고 트레이 아이콘도 없으며,
오른쪽 클릭 **종료**로 닫습니다.

## 로컬 브리지와 개인정보 경계

기본 URL: `http://127.0.0.1:37421`. 브리지는 루프백 인터페이스에만 바인딩되는 작은 HTTP
서버입니다.

| 요청 | 응답 |
| --- | --- |
| `GET /health` | `200` `{"ok":true,"v":1}` |
| `POST /state` | `204`, 본문 없음 |
| `OPTIONS /state`, `OPTIONS /health` | CORS 헤더와 함께 `204`(`Access-Control-Allow-Origin: *`, 메서드 `GET, POST, OPTIONS`) |
| 알 수 없는 경로 | `404` |
| 잘못된 JSON, 알 수 없는 장면, 누락/잘못된 길이, 8 KB 초과 본문 | `400` |

`POST /state` 페이로드(최대 8 KB, 알 수 없는 필드는 무시):

```json
{"v": 1, "scene": "typing", "character": "girl", "scale": 1, "animation": true, "updatedAt": 1780000000000}
```

`scene`은 15개 장면 id 중 하나입니다(`idle`, `typing`, `thinking`, `planning`, `reading`,
`searching`, `working`, `success`, `waiting`, `error`, `tired`, `coffee`, `sleeping`,
`debugging`, `offline`). 매 게시마다 `scene`만 사용되며, `character`는 캐릭터가 저장되기 전
첫 실행에서만 채택됩니다. `scale`과 `animation`은 데스크톱 메뉴의 몫이고 `updatedAt`은
정보용입니다.

브리지를 건너는 것은 표시 상태뿐입니다. **프롬프트 텍스트, 초안 텍스트, 메시지, 세션 id,
파일 경로, 모델 출력은 절대 전송되지 않습니다**. 브리지는:

- `127.0.0.1`에만 바인딩되고 인증, 쿠키, TLS가 없습니다.
- 8 KB를 넘는 요청 본문과 장면 id가 알 수 없는 본문을 거부합니다.
- 요청 페이로드를 기록하지 않고 파일을 제공하지 않습니다.
- 로컬 페이지가 게시할 수 있도록 CORS로 브라우저 오리진만 허용합니다.

## 만료와 오프라인 동작

창은 마지막으로 받은 상태와 도착 시간을 기억합니다. 10초 넘게 상태가 도착하지 않으면
`effective_scene`이 `offline`이 되고, 새 게시가 올 때까지 창은 계속 렌더링하며 모션이
켜져 있으면 그 장면 애니메이션도 계속 재생합니다. 페이지 측도 이를 반영하여 상태 확인이나
게시가 실패하면 설정 행이 **실행 중이 아님**으로 돌아갑니다.

정확히 10.000초는 아직 신선하며, 전환은 그 직후에 일어납니다. `--self-test`가 주입된
시계로 이 경계를 확인합니다.

## 검증

헤드리스 부분은 검증했습니다:

```sh
python3 -m py_compile desktop/companion.py
python3 desktop/companion.py --self-test
```

자체 테스트는 두 캐릭터 × 15개 장면을 0.5, 1.0, 2.0 배율로 디코드하고 Deepy의 선택적
`roaming` 애니메이션도 확인하며, 프레임 크기와 지속 시간을 검사하고, 장면당 첫 프레임
PNG 30개를 저장소 밖 임시 디렉터리에 시각 증거로 작성합니다. 이어서 임시 포트에서 브리지를
시작해 `GET /health`, 두 CORS 프리플라이트, 유효한 `POST /state`, 잘못된/알 수 없는 장면
본문(`400`), 알 수 없는 경로(`404`)를 테스트한 뒤 10초 만료 규칙을 확인합니다. `ok:` 요약
(`ok: … 92 animated decodes, 31 still decodes, 30 evidence PNGs, 260 checks`)을 출력하고
실패 시 비영으로 종료합니다.

roaming 전환 테스트도 통과합니다
(`whale: moving→roaming, released→idle; girl: no roaming`). 브라우저 측 페이로드는
헤드리스 React 렌더에서 검증했으며(`scene=typing` → `success`), 요청 본문에 초안이나
세션 데이터가 없습니다. 헤드리스 브라우저 드래그 테스트에서는 고래가 드래그 중
`roaming`으로 전환되고 놓으면 장면으로 돌아옵니다(소녀는 그대로).

그래픽 세션 없이는 확인할 수 없는 부분: 실제 창, Cairo 브리지가 없는 머신의 픽셀 단위
투명(불투명 폴백 예상), 항상 위와 드래그 동작, Wayland 창 위치 지정.

## 제한 사항

- 그래픽 세션(X11 또는 Wayland)이 필요합니다. 헤드리스 서버나 순수 WSL에는 디스플레이가
  없으므로 X 포워딩이나 가상 디스플레이를 사용하거나 `--self-test`를 실행하세요.
- Wayland 합성기는 요청한 창 위치를 무시할 수 있고 일부 백엔드는 창 이동 요청을
  거부합니다. X11 세션이 가장 예측 가능합니다.
- 트레이 아이콘, 알림, 창 장식, 텍스트가 없습니다. 종료는 오른쪽 클릭 **종료**(또는
  **1시간 숨기기**)로 합니다.
- 실시간 상태를 위해서는 페이지가 열려 있어야 합니다. 창은 표시 대상이며 두 번째
  클라이언트가 아닙니다.
- 같은 머신 전용입니다. 브리지는 루프백 전용이고 인증이 없으므로 포트를 노출하지 마세요.
  창은 작은 페이로드 외에는 대화에 접근할 수 없습니다.
- HTTPS로 제공되는 페이지는 보통 `http://127.0.0.1` 요청을 혼합 콘텐츠로 차단합니다.
  일반적인 `http://127.0.0.1:3080` 페이지를 사용하세요.

## 문제 해결

| 증상 | 확인 사항 |
| --- | --- |
| 창이 전혀 나타나지 않음 | 디스플레이가 있나요? 먼저 `python3 desktop/companion.py --self-test`를 실행하고, 서버에서는 X 포워딩이나 가상 디스플레이를 사용하세요. |
| `cannot listen on 127.0.0.1:37421` | 다른 컴패니언 인스턴스가 실행 중입니다. 종료하세요(페이지가 37421을 사용하므로 기본 포트 유지가 가장 간단합니다). |
| 투명 대신 단색 어두운 사각형 | `python3-cairo`를 설치하고 합성 창 관리자와 X11 또는 합성 Wayland 세션을 사용하세요. 예상된 불투명 폴백이며 크래시가 아닙니다. |
| 장면이 계속 `offline` | 페이지가 열려 있고, 번들이 활성화되어 있으며, **데스크톱 창**이 체크되어 있나요? `curl http://127.0.0.1:37421/health`와 페이지·창이 같은 포트를 쓰는지 확인하세요. |
| 창이 열려 있는데 설정에 **실행 중이 아님**이 표시됨 | 페이지가 브리지에 도달하지 못합니다. 포트, 로컬 방화벽, 37421을 사용하는 다른 프로세스, HTTPS 페이지(혼합 콘텐츠)를 확인하세요. |
| Wayland에서 창을 옮길 수 없음 | 합성기가 이동 요청을 무시할 수 있습니다. X11 세션을 시도하거나 스프라이트의 다른 위치에서 드래그하세요. |
| 창이 잘못된 모니터에 있거나 화면 밖에 있음 | 오른쪽 클릭 메뉴의 **위치 초기화**를 사용하세요. 일부 Wayland 합성기는 위치 지정을 완전히 무시합니다. |
