# Установка

[English](../installation.md) | [中文](../zh/installation.md) | Русский | [Tiếng Việt](../vi/installation.md) | [日本語](../ja/installation.md) | [한국어](../ko/installation.md)

`dsh-pixel-companions` — это dsh **бандл-пакет**. У него есть половина Host, которая ничего
не делает, и браузерная половина (`client.js`), которая рисует компаньона в слоте
`shell.overlay` на весь фрейм, поэтому пакет нужно установить в профиль dsh, а отдавать его
должен запущенный процесс `dsh web`.

Собранный `client.js` и графика в `assets/` закоммичены в репозиторий; маршрут ассетов
Harness отдаёт эти файлы из установленного пакета, поэтому для установки **не нужен шаг
сборки** и не нужен Node-инструментарий.

## Требования

- CLI `dsh` с инициализированным профилем Web (`dsh web`). Каталог профиля —
  `$DSH_HOME/profiles/web`, где `$DSH_HOME` по умолчанию равен `~/.dsh`.
- `pnpm` в `PATH`. `dsh plugin` передаёт свои аргументы в pnpm в каталоге профиля.
- Node.js 22.6+ только для пересборки бандла из исходников.
- Опциональному окну на рабочем столе нужны Python 3.10+ с GTK 3 и Pillow на той же
  машине; см. [desktop.md](../desktop.md).

## Установка из локальной рабочей копии

```sh
git clone https://github.com/kappyra/dsh-pixel-companions.git
cd dsh-pixel-companions
dsh plugin --profile web add link:"$PWD"
```

- `link:` устанавливает рабочую копию как pnpm-ссылку, а не копирует её, поэтому изменения
  в копии отдаются без переустановки.
- Абсолютный каталог тоже подходит: `dsh plugin --profile web add /path/to/dsh-pixel-companions`.
- Добавление бандла дописывает имя пакета в `dsh.profile.bundles` в `package.json` профиля —
  именно это его и включает.

## Установка из Git-адреса или tarball

```sh
dsh plugin --profile web add github:kappyra/dsh-pixel-companions
# or
npm pack
dsh plugin --profile web add /path/to/dsh-pixel-companions-0.1.0.tgz
```

Git-установка забирает закоммиченный `client.js`; на машине, где идёт установка, сборка не
запускается. Пакет не объявляет install-скриптов, поэтому pnpm не должен спрашивать
подтверждение на их выполнение.

## Активация

`dsh plugin` записывает профиль, но не перезапускает работающий Host. В поставляемом профиле
Web транспорт `dsh-hmr` отслеживает изменения профиля, и страница подхватывает новый бандл —
обычно за секунду-другую. Если этого не произошло:

1. Перезагрузите веб-страницу (при сомнениях — жёсткой перезагрузкой).
2. Если компаньон так и не появился, перезапустите процесс Web (`Ctrl+C`, затем `dsh web`)
   и перезагрузите страницу.

После перезагрузки компаньон появляется у правого нижнего края окна, над областью ввода. Он
живёт в overlay на весь фрейм, поэтому виден на **каждой странице** веб-интерфейса — диалог,
настройки, плагины — и переживает переходы между страницами: смена страницы не размонтирует
его, заново бандл запускает только полная перезагрузка. Открытый диалог не обязателен: без
смонтированной сессии компаньон переходит к поведению idle/sleeping. Перетаскивайте его левой
кнопкой мыши, касанием или пером в любое место окна; кнопка с шестерёнкой рядом открывает
панель настроек.

## Проверка

- **Настройки → Плагины → Список плагинов** показывает элемент с именем `Pixel companions` и
  этим описанием (из `locale/*.json`).
- Компаньон виден на каждой странице (диалог, настройки, плагины), а не только над полосой
  ввода.
- Перетаскивание двигает его; если отпустить у края окна, он остаётся на экране; перезагрузка
  страницы восстанавливает перетащенную позицию.
- Шестерёнка открывает панель настроек с персонажем, масштабом, языком, анимацией, показом,
  сбросом позиции, сеткой предпросмотра 15 сцен, «Авто» и «Закрыть».
- Host собрал ваш бандл: `dsh --profile web --dump-config` выводит строку для
  `dsh-pixel-companions`.
- Скрытый bridge фактов не добавляет в полосу ввода видимого DOM; рисует только overlay.
- *(Опционально)* Когда окно на рабочем столе запущено и включено **«Окно на рабочем
  столе»**, строка в панели с шестерёнкой читается как **«Подключено»**, а окно зеркалирует
  текущую сцену.

## Опционально: окно на рабочем столе

Компаньона можно зеркалировать в отдельное окно на рабочем столе на той же машине. Это отдельный
процесс Python, а не ещё один бандл — в профиль ничего дополнительно не устанавливается:

```sh
sudo apt install python3-gi gir1.2-gtk-3.0 python3-cairo
python3 -m pip install --user Pillow
python3 desktop/companion.py        # or ./desktop/run.sh
```

Затем отметьте **«Окно на рабочем столе»** в панели с шестерёнкой компаньона. Оно выключено по
умолчанию, поэтому страница не трогает порт рабочего стола, пока вы его не включите. Чтобы
состояние было живым, страница должна оставаться открытой, а обе половины должны работать на
одной машине (bridge слушает только loopback). Полное руководство:
[desktop.md](../desktop.md).

## Отключение, удаление, обновление

- **Отключить**, не удаляя: переключите бандл в «Настройки → Плагины» или уберите его из
  `dsh.profile.bundles` в `$DSH_HOME/profiles/web/package.json`. Компаньон исчезнет со всех
  страниц.
- **Удалить**: `dsh plugin --profile web remove dsh-pixel-companions` или страница «Плагины».
- **Обновить link-копию**: `git pull`, затем `npm install && npm run build` и перезагрузка;
  транспорт HMR подменит пересобранный `client.js`. Изменение `package.json` требует
  перезапуска Host.
- **Удалить Git-установку**: `dsh plugin --profile web remove dsh-pixel-companions` удаляет
  зависимость и запись бандла.

## Страница плагинов вместо CLI

Страница «Плагины» в веб-интерфейсе устанавливает через тот же путь pnpm:

1. Боковая панель → **Плагины**.
2. **Добавить плагин** (или стрелка → **Установить сторонний плагин**).
3. Введите тот же spec, который передали бы в `dsh plugin add`.
4. **Установить**, затем **Включить сейчас**.

## Диагностика неудачной активации

- Вывод pnpm и лог установки хранятся в `$DSH_HOME/profiles/web/.plugin-manager/logs/`.
- Неудачный запуск восстанавливает `package.json` и lockfile профиля.
- Если страница сообщает о бандле, который «loaded without registering» модуль Client, проверьте,
  что `client.js` начинается с `window.__ModuleLoader__.load({ id: "dsh-pixel-companions"`, и
  что имя пакета в `package.json` по-прежнему равно id модуля.
