# Сцены

[English](../scenes.md) | [中文](../zh/scenes.md) | Русский | [Tiếng Việt](../vi/scenes.md) | [日本語](../ja/scenes.md) | [한국어](../ko/scenes.md)

Компаньон показывает ровно одну сцену за раз. Сцена выбирается по живым фактам, которые
веб-клиент уже публикует; ничего не выводится из текста промпта, вызов модели не делается, и
собственный набор пользователя сцену не меняет. Правила живут в `src/client/state.ts`
(`deriveScene`) и покрыты `tests/state.test.ts`. Подписи сцен локализованы на шесть языков
(`src/client/text.ts`, `SCENE_LABELS`); сами правила от языка не зависят.

## Входные данные

| Факт | Источник | Значение |
| --- | --- | --- |
| `running` | `SessionSnapshot.running` через bridge фактов | На Host идёт ход |
| `pendingInteraction` | `useSessionStatus(…)` → `status.pendingInteraction` | Подтверждение или вопрос ждёт пользователя |
| `inputPhase` | `InputState.phase` через bridge фактов | `plain`, `adjudicating`, `claimed`, `submitting`, `sending` |
| `toolRunning` | непустой `ChatSnapshot.legacy.runningCalls` через bridge | Прямо сейчас выполняется вызов инструмента |
| `assistantStream` | `ChatSnapshot.legacy.partial.blocks[].kind` плюс непустой `text` (`reasoning` или `text`) через bridge | Что ассистент стримит прямо сейчас |
| `error` | `SessionSnapshot.promptError` или `lastAgentError` | Сообщена ошибка отправки или агента |
| `openError` | `SessionSnapshot.openState === 'error'` | История сессии не открылась |
| `runningMs` | время с момента, когда `running` стал true | Длительность текущего хода |
| `idleMs` | время с последнего изменения сессии или хода | Используется таймером сна |
| `flash` | локальный таймер 4.8 с после неудачной остановки | Вспышка ошибки; успешные остановки вместо этого закрепляются |

Живые биты доходят до overlay как `CompanionFacts.live` (1 = выполняется вызов инструмента,
2 = стримятся рассуждения, 4 = стримится текст ответа) и публикуются в том же кадре, что и
снимок Chat, поэтому живые смены сцены фактически мгновенны. Часы с шагом 1 с используются только
для порогов по прошедшему времени и для таймера сна.

Факты публикует скрытый bridge-элемент в `conversation.input.dock`, а читает overlay. Когда
диалог не смонтирован, последние факты сохраняются с `connected: false` и `running: false`,
поэтому overlay переходит к поведению idle/sleeping. Ожидающее взаимодействие всё равно видно
на страницах без диалога, потому что overlay сам подписан на `useSessionStatus`.

## Порядок правил

Срабатывает первое подходящее правило:

```text
openError                          -> error
pendingInteraction                 -> waiting
inputPhase sending/submitting/adjudicating -> typing
toolRunning                        -> working
assistantStream === 'reasoning'    -> thinking
assistantStream === 'answer'       -> typing
running:
    runningMs > 180 000            -> coffee
    runningMs >  75 000            -> tired
    otherwise                      -> thinking   (request in flight, no live stream)
flash === 'error' or error         -> error
flash === 'success'                -> success
idleMs > 110 000                   -> sleeping
otherwise                          -> idle
```

Правило `flash` для `success` всё ещё есть в `deriveScene`, но overlay больше не выдаёт
вспышку успеха по таймеру: успешная остановка применяется как закреплённое завершение
`success` (см. ниже). Своё окно в 4.8 с сохраняет только вспышка ошибки. Живые биты не привязаны
к часам, поэтому гранулярность около 1 с имеют только пороги по прошедшему времени
(`tired` / `coffee`) и таймер сна.

## Закреплённое завершение и панель подробностей

Успешная остановка закрепляется: overlay держит `success` и свой однострочный отчёт, пока
пользователь не наведёт курсор на компаньона (выдержка 320 мс не даёт указателю, проходящему
над спрайтом по пути к отчёту, закрыть его) или не начнётся новый ход. Наведение закрывает
карточку, и сцена возвращается к `idle`/`sleeping`; новый завершённый ход снова её открывает.
Компаньон не засыпает, пока готовый результат ждёт, когда его увидят.

Строка отчёта показывает предпросмотр и локализованную кнопку **«Подробнее»**. Она открывает
прокручиваемую панель с полным финальным ответом как простым текстом — экранированным React,
без рендеринга HTML или markdown, с сохранёнными переносами строк, не более 8000 символов и с
многоточием в конце, — расположенную над компаньоном или под ним и ограниченную областью
просмотра. Панель закрывается по ✕, Escape или нажатию вне её и скрывается, когда завершение
закрыто. Текст отчёта сохраняет `role="status"` / `aria-live="polite"`, кнопка выставляет
`aria-expanded`, а панель — это `role="dialog"` с заголовком **«Отчёт»** (локализован на всех
шести языках). Пока панель открыта, она заменяет карточку отчёта и ввода; её закрытие
возвращает карточку.

Отчёт и строка ввода при наведении делят одну ограниченную областью просмотра колонку,
привязанную под компаньоном (или над ним). Пока отчёт виден, ввод стоит прямо под ним, а кнопка
подробностей остаётся в строке отчёта; наведение на отчёт держит его открытым и показывает
ввод. Наведение на компаньона закрывает отчёт после выдержки 320 мс, и после этого ввод стоит
прямо под компаньоном. Уход с отчёта снова скрывает ввод, а отчёт остаётся, пока не наведут
курсор на спрайт или не начнётся новый ход. Колонка и панель подробностей следуют выбранному
размеру компаньона (слайдер **«Размер»** охватывает от 50 % до 200 %, есть кнопки-пресеты
50/100/150/200 %; тот же элемент есть в **«Настройки → Общие → Размер компаньона»**).

## Визуализация движения (`roaming`)

`roaming` — визуализация движения, а не сцена: её нет в `SCENES`, её никогда не возвращает
`deriveScene`, у неё нет подписи и правила. Пока пользователь перетаскивает Deepy, overlay
рисует вместо текущей сцены его опциональную анимацию без стола `roaming`, поэтому стол, ноутбук,
лампа и пол не едут вместе с ним; при отпускании текущая сцена возвращается. У Whale Girl нет
ассета roaming, и во время движения она сохраняет спрайт своей сцены. Окно на рабочем столе
делает то же самое, пока его перемещают. Правила из 15 состояний выше не изменились.

## Что означает каждая сцена

| Сцена | Безопасное прочтение |
| --- | --- |
| `idle` | Ничего не наблюдается |
| `typing` | Отправка в пути или ассистент стримит текст ответа |
| `working` | Выполняется вызов инструмента |
| `thinking` | Ассистент стримит рассуждения или запрос к модели в пути — но никогда набор пользователя |
| `tired` | Долгий ход без живого сигнала — аналогия, а не усталость модели |
| `coffee` | Очень долгий ход без живого сигнала — только для вида |
| `waiting` | Что-то ждёт пользователя |
| `success` | Ход остановился без замеченной ошибки — включает отмены; закрепляется, пока вы не наведёте курсор на компаньона или не начнётся новый ход |
| `error` | Настоящий сигнал ошибки |
| `sleeping` | Нет изменений сессии 110 с — только отображение |
| `planning`, `reading`, `searching`, `debugging`, `offline` | Только ручной предпросмотр; типизированных сигналов для них у клиента пока нет |

`thinking` — про работу самого ассистента и никогда про набор сообщения пользователем: набор
черновика ничего не меняет, и компаньон остаётся `idle`, пока ассистент действительно не начнёт
работать. Никогда не подавайте `tired`, `coffee`, `sleeping` или `success` как факты о модели.
Это метафоры представления поверх приблизительного состояния клиента.

## Ручной предпросмотр

Панель с шестерёнкой перечисляет все 15 сцен миниатюрами, с подписями на выбранном языке
интерфейса. Выбор одной принудительно включает эту сцену, пока не нажато **«Авто»** или не
изменится сессия; принудительная сцена никогда не сохраняется. В панели также есть
**«Закрыть»** (Escape тоже её закрывает).

## Добавление или переименование сцены

1. Добавьте сцену в `SCENES` в `src/client/state.ts` и правило для неё в `deriveScene`.
2. Добавьте её подпись в `SCENE_LABELS` в `src/client/text.ts` для всех шести языков.
3. Добавьте `assets/girl/<scene>.{webp,png}` и `assets/whale/<scene>.{webp,png}` (192×128,
   прозрачный фон; 16 кадров по 120 мс для WebP).
4. `npm run build` — манифест ассетов и сборщик клиента подхватят новые файлы.
5. Расширьте `tests/state.test.ts` для нового правила.

## Уменьшенная анимация

Когда совпадает `prefers-reduced-motion: reduce` или пользователь выключает **«Анимацию»**,
вместо анимированного WebP рисуется статичный PNG для сцены. Проверка выполняется при каждой
смене сцены, поэтому изменение на уровне ОС подхватывается без перезагрузки.
